# Unit 6: Backtracking and Branch & Bound

## Topic 6.5 — Travelling Salesman Problem (TSP) Using Branch & Bound

## 1. Introduction

The **Travelling Salesman Problem (TSP)** is a classic **combinatorial optimization problem**.

### Problem Statement

Given a set of cities and the cost/distance between every pair of cities, find a tour that:

1. Starts from a city.
2. Visits every city **exactly once**.
3. Returns to the starting city.
4. Has the **minimum total cost**.

### Example

For cities:

```text
A, B, C, D
```

A valid tour could be:

```text
A → B → C → D → A
```

The goal is to find the tour with the minimum cost.

---

# 2. Example

Consider the following cost matrix:

|       |  A |  B |  C |  D |
| ----- | -: | -: | -: | -: |
| **A** |  0 | 10 | 15 | 20 |
| **B** | 10 |  0 | 35 | 25 |
| **C** | 15 | 35 |  0 | 30 |
| **D** | 20 | 25 | 30 |  0 |

Consider the tour:

```text
A → B → C → D → A
```

Cost:

$$
10+35+30+20=95
$$

Another tour:

```text
A → C → B → D → A
```

Cost:

$$
15+35+25+20=95
$$

The algorithm examines possible tours while using **Branch and Bound** to avoid unnecessary exploration.

---

# 3. Why TSP is Difficult

For `n` cities, fixing the starting city leaves approximately:

$$
(n-1)!
$$

possible tours.

For example:

| Cities | Possible tours |
| -----: | -------------: |
|      4 |              6 |
|      5 |             24 |
|      6 |            120 |
|     10 |        362,880 |
|     15 | 87,178,291,200 |

Therefore, checking every possible tour becomes expensive as the number of cities increases.

---

# 4. Branch and Bound Approach

TSP is a **minimization problem**.

The algorithm builds the tour step-by-step.

```text
                    A
              /     |     \
             B      C      D
            / \    / \    / \
           C   D  B   D  B   C
          ... ... ... ... ... ...
```

At each node:

1. **Branch** into possible next cities.
2. Calculate a **lower bound** for the possible tour cost.
3. Compare it with the current best tour.
4. **Prune** the branch if it cannot produce a better tour.

---

# 5. Lower Bound

Since TSP is a minimization problem, we calculate a **lower bound**.

The lower bound represents the minimum possible cost that could be achieved from the current partial tour.

Suppose:

```text
Current Best Tour Cost = 100
```

For a particular branch:

```text
Lower Bound = 120
```

Since even the optimistic minimum cost is already:

```text
120 > 100
```

this branch cannot produce a better solution.

Therefore:

```text
Prune
```

---

# 6. Pruning Condition

For a **minimization problem**:

$$
\boxed{LowerBound \geq BestCost \Rightarrow Prune}
$$

### Example

```text
Best Cost = 95
Lower Bound = 110
```

Therefore:

```text
110 ≥ 95
```

Prune the branch.

But:

```text
Best Cost = 95
Lower Bound = 80
```

Since:

```text
80 < 95
```

the branch may contain a better solution.

Therefore:

```text
Explore
```

---

# 7. State-Space Tree

Suppose we start at city `A`.

```text
                         A
                    /    |    \
                   B     C     D
                  / \   / \   / \
                 C   D B   D B   C
                 ...
```

A node represents a **partial tour**.

For example:

```text
A → B → C
```

means:

* Start at A.
* Visit B.
* Visit C.
* Cities still remaining: D.

The algorithm calculates the lower bound for this partial tour.

---

# 8. Basic Steps

```text
1. Start from a selected city.
2. Create the root node.
3. Calculate its lower bound.
4. Select a promising node.
5. Branch to an unvisited city.
6. Calculate the lower bound of each child.
7. If the bound is worse than the current best:
       Prune.
8. Otherwise:
       Continue exploring.
9. When a complete tour is obtained:
       Calculate its cost.
10. Update the best tour if necessary.
11. Continue until all promising nodes are processed.
```

---

# 9. Simple Lower-Bound Calculation

One common approach uses the **two smallest outgoing edges** for each city.

For each city, find its two smallest edge costs.

For example, for city A:

```text
A → B = 10
A → C = 15
A → D = 20
```

The two smallest are:

```text
10 and 15
```

For city B:

```text
B → A = 10
B → D = 25
B → C = 35
```

The two smallest are:

```text
10 and 25
```

This provides an optimistic estimate of the tour cost.

> The exact bound formula depends on the implementation. The important concept is that the bound must not underestimate the minimum possible completion cost in a way that causes a potentially optimal branch to be incorrectly pruned.

---

# 10. Lower Bound Intuition

Think of the lower bound as asking:

> "What is the absolute minimum cost this partial tour could possibly have?"

For example:

```text
Partial Tour Cost = 40
Estimated remaining minimum = 50

Lower Bound = 90
```

If:

```text
Current Best = 85
```

then:

```text
90 ≥ 85
```

so this branch cannot improve the current best.

```text
Prune
```

---

# 11. Example of Branching

Suppose:

```text
Current path:

A → B
```

Unvisited cities:

```text
C, D
```

Two possible branches:

```text
              A → B
              /   \
             C     D
            /       \
           D         C
```

They represent:

```text
A → B → C → D → A
```

and

```text
A → B → D → C → A
```

The algorithm calculates a bound before deciding whether both branches need to be explored.

---

# 12. Complete Tour

A complete tour has visited every city.

For example:

```text
A → B → C → D → A
```

Cost:

```text
A→B = 10
B→C = 35
C→D = 30
D→A = 20
```

Therefore:

$$
Cost = 10+35+30+20 = 95
$$

If:

```text
Best Cost = 110
```

then:

```text
95 < 110
```

Update:

```text
Best Cost = 95
Best Tour = A → B → C → D → A
```

# 13. Branch and Bound Dry Run

Using the previous matrix:

```text
                A
             /  |  \
            B   C   D
```

Suppose the algorithm first finds:

```text
A → B → C → D → A
Cost = 95
```

So:

```text
Best = 95
```

Now consider another partial branch.

Suppose:

```text
Lower Bound = 105
```

Since:

$$
105 \geq 95
$$

we can immediately discard it.

```text
Branch
  ↓
Lower Bound = 105
  ↓
Best = 95
  ↓
Prune
```

There is no need to complete that branch.

# 14. TSP Using Backtracking vs Branch and Bound

TSP can be solved using backtracking by generating permutations of cities.

Branch and Bound improves this approach by using cost bounds.

| Feature      | Backtracking            | Branch & Bound          |
| ------------ | ----------------------- | ----------------------- |
| Main idea    | Explore possible tours  | Explore promising tours |
| Branching    | Possible next cities    | Possible next cities    |
| Pruning      | Constraint-based        | Bound-based             |
| Objective    | Find valid/optimal tour | Find minimum-cost tour  |
| Bound        | Not required            | Required                |
| Search space | Very large              | Reduced using bounds    |

# 15. Java Implementation

The following implementation uses a simple lower-bound technique based on the two smallest edges from each city.

```java id="3i9h2k"
import java.util.*;

public class TSPBranchBound {

    static int N = 4;
    static int[][] cost = {
        {0, 10, 15, 20},
        {10, 0, 35, 25},
        {15, 35, 0, 30},
        {20, 25, 30, 0}
    };

    static boolean[] visited = new boolean[N];
    static int bestCost = Integer.MAX_VALUE;
    static List<Integer> bestPath = new ArrayList<>();

    static int firstMin(int city) {

        int min = Integer.MAX_VALUE;

        for (int j = 0; j < N; j++) {
            if (j != city && cost[city][j] < min) {
                min = cost[city][j];
            }
        }

        return min;
    }

    static int secondMin(int city) {

        int first = Integer.MAX_VALUE;
        int second = Integer.MAX_VALUE;

        for (int j = 0; j < N; j++) {

            if (j == city)
                continue;

            if (cost[city][j] <= first) {
                second = first;
                first = cost[city][j];
            }
            else if (cost[city][j] < second) {
                second = cost[city][j];
            }
        }

        return second;
    }

    static int initialBound() {

        int bound = 0;

        for (int i = 0; i < N; i++) {
            bound += firstMin(i) + secondMin(i);
        }

        return (bound + 1) / 2;
    }

    static void tsp(
            int current,
            int currentCost,
            int bound,
            List<Integer> path) {

        if (path.size() == N) {

            int totalCost =
                currentCost + cost[current][0];

            if (totalCost < bestCost) {

                bestCost = totalCost;

                bestPath = new ArrayList<>(path);
                bestPath.add(0);
            }

            return;
        }

        for (int next = 0; next < N; next++) {

            if (!visited[next]) {

                int newCost =
                    currentCost + cost[current][next];

                if (newCost >= bestCost)
                    continue;

                visited[next] = true;
                path.add(next);

                tsp(
                    next,
                    newCost,
                    bound,
                    path
                );

                path.remove(path.size() - 1);
                visited[next] = false;
            }
        }
    }

    public static void main(String[] args) {

        int bound = initialBound();

        visited[0] = true;

        List<Integer> path = new ArrayList<>();
        path.add(0);

        tsp(0, 0, bound, path);

        System.out.println(
            "Minimum Cost = " + bestCost
        );

        System.out.print("Tour = ");

        for (int city : bestPath) {
            System.out.print(city + " ");
        }
    }
}
```

### Important note

This code demonstrates the **state-space search and pruning structure**. A production-quality Branch and Bound implementation should update the bound for every child node and use it in the pruning decision, rather than relying only on the current partial cost.

# 16. A Clearer TSP Branch-and-Bound Structure

The essential logic is:

```text
function TSP(node):

    if complete tour:
        update best
        return

    for each unvisited city:

        create child

        calculate lower bound

        if lower bound < best cost:
            TSP(child)
        else:
            prune child
```

This is the core algorithm students should understand.

# 17. C++ Implementation Structure

```cpp id="l4kj6m"
#include <iostream>
#include <vector>
#include <climits>
using namespace std;

int n = 4;

int cost[4][4] = {
    {0, 10, 15, 20},
    {10, 0, 35, 25},
    {15, 35, 0, 30},
    {20, 25, 30, 0}
};

bool visited[4];

int bestCost = INT_MAX;
vector<int> bestPath;

void tsp(int current,
         int currentCost,
         vector<int>& path) {

    // Complete tour
    if (path.size() == n) {

        int total =
            currentCost + cost[current][0];

        if (total < bestCost) {

            bestCost = total;
            bestPath = path;
            bestPath.push_back(0);
        }

        return;
    }

    for (int next = 0; next < n; next++) {

        if (!visited[next]) {

            int newCost =
                currentCost + cost[current][next];

            // Simple pruning
            if (newCost >= bestCost)
                continue;

            visited[next] = true;
            path.push_back(next);

            tsp(next, newCost, path);

            path.pop_back();
            visited[next] = false;
        }
    }
}

int main() {

    visited[0] = true;

    vector<int> path;
    path.push_back(0);

    tsp(0, 0, path);

    cout << "Minimum Cost = "
         << bestCost << endl;

    cout << "Tour = ";

    for (int city : bestPath) {
        cout << city << " ";
    }

    return 0;
}
```

### Output

For the given matrix, one optimal tour is:

```text
Minimum Cost = 80
Tour = 0 1 3 2 0
```

The corresponding tour is:

```text
A → B → D → C → A
```

Cost:

$$
10+25+30+15=80
$$

# 18. Important Correction in Understanding TSP

Do not confuse:

### Hamiltonian Cycle

Question:

> Does there exist a cycle that visits every vertex exactly once?

This is primarily a **decision problem**.

### TSP

Question:

> Which tour visiting every city exactly once has the minimum total cost?

This is an **optimization problem**.

Both involve visiting every vertex exactly once, but their objectives are different.

---

# 19. Complexity

TSP has a very large search space.

With a fixed starting city:

$$
(n-1)!
$$

possible tours need to be considered in a brute-force approach.

Branch and Bound can substantially reduce the number of tours explored by pruning, but its **worst-case time complexity remains exponential/factorial**.

Therefore:

```text
Branch & Bound
≠
Polynomial-time solution
```

It is an optimization of the search process.

# 21. Common Mistakes

### Mistake 1: Forgetting the return to the starting city

A TSP tour must be:

```text
A → B → C → D → A
```

not:

```text
A → B → C → D
```

---

### Mistake 2: Using the wrong pruning condition

TSP is a minimization problem.

Correct:

$$
\boxed{LowerBound \geq BestCost \Rightarrow Prune}
$$

---

### Mistake 3: Visiting a city twice

Each city must be visited exactly once before returning to the starting city.

---

### Mistake 4: Confusing TSP with shortest path

A shortest-path algorithm finds a path between specified vertices.

TSP requires:

```text
Visit ALL cities exactly once
+
Return to start
+
Minimize total cost
```

```text
                    TSP
                     |
              Select starting city
                     |
                 Branch
                     ↓
             Select next city
                     ↓
             Calculate Bound
                     ↓
             Compare with Best

                ↓          ↓

                |
          Complete Tour?
                ↓
          Add return edge
                ↓
          Update Best Cost
```

### Remember

**TSP objective:**

$$
\boxed{\text{Visit every city exactly once and return to start with minimum cost}}
$$

**Minimization pruning:**

$$
\boxed{LowerBound \geq BestCost \Rightarrow Prune}
$$

**Search space:**

$$
\boxed{(n-1)!}
$$

**Main Branch & Bound idea:**

```text
Branch → Calculate Lower Bound → Compare → Explore / Prune
```
