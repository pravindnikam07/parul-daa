# Unit 7: String Matching & NP Completeness

## Topic 7.7 — P Class Problems

## 1. Introduction

**P** stands for **Polynomial Time**.

The class **P** contains decision problems that can be **solved by a deterministic algorithm in polynomial time**.

In simple terms:

> A problem belongs to P if an algorithm can solve it efficiently, where the running time is bounded by a polynomial function of the input size.

---

## 2. Polynomial Time

An algorithm has polynomial-time complexity if its running time can be expressed as:

$$
O(n^k)
$$

where:

* `n` = input size
* `k` = constant

Common examples:

$$
O(n)
$$

$$
O(n^2)
$$

$$
O(n^3)
$$

$$
O(n\log n)
$$

are considered polynomial-time complexities.

---

## 3. Examples of Polynomial-Time Algorithms

Some common algorithms that run in polynomial time are:

| Algorithm / Problem   | Typical Complexity |
| --------------------- | -----------------: |
| Linear Search         |             `O(n)` |
| Binary Search         |         `O(log n)` |
| Bubble Sort           |            `O(n²)` |
| Insertion Sort        |            `O(n²)` |
| Merge Sort            |       `O(n log n)` |
| BFS                   |         `O(V + E)` |
| DFS                   |         `O(V + E)` |
| Dijkstra's Algorithm* |         Polynomial |
| Kruskal's Algorithm   |         Polynomial |
| Prim's Algorithm      |         Polynomial |

*The exact complexity depends on the implementation and data structure used.

---

# 4. Decision Problems in P

For complexity-class discussions, problems are generally expressed as **decision problems**.

A decision problem has only two possible answers:

```text
YES
NO
```

### Example: Path Existence

Instead of:

> Find a path from A to B.

we can ask:

> Does a path from A to B exist?

Answer:

```text
YES
```

or:

```text
NO
```

BFS or DFS can solve this efficiently.

Therefore, this decision problem belongs to P.

---

# 5. Example: Binary Search

Consider the sorted array:

```text
10 20 30 40 50 60 70
```

Search for:

```text
50
```

Binary Search repeatedly divides the search space into two parts.

Complexity:

$$
O(\log n)
$$

Since:

$$
O(\log n)
$$

is polynomially bounded, Binary Search is a polynomial-time algorithm.

---

# 6. Example: Sorting

Consider:

```text
8 3 5 1 9
```

Merge Sort divides the array and combines the sorted parts.

Its complexity is:

$$
O(n\log n)
$$

Therefore, it is a polynomial-time algorithm.

---

# 7. Example: Graph Reachability

Suppose:

```text
A → B → C → D
```

Question:

> Is vertex D reachable from A?

BFS or DFS can answer this.

Using BFS:

```text
Start A
 ↓
B
 ↓
C
 ↓
D
```

Time complexity:

$$
O(V+E)
$$

where:

* `V` = number of vertices
* `E` = number of edges

This is polynomial.

---

# 8. P Does Not Mean "Fast"

An important point:

> **Polynomial time does not necessarily mean practically fast.**

For example:

$$
O(n^{10})
$$

is polynomial, but it can become extremely expensive for large inputs.

Therefore:

```text
Polynomial
≠
Always practically fast
```

The P class is a **theoretical complexity classification**.

---

# 9. P vs Exponential Time

Compare:

### Polynomial

$$
O(n^2)
$$

### Exponential

$$
O(2^n)
$$

For increasing `n`, exponential functions grow much faster.

Example:

|  n | `n²` |          `2ⁿ` |
| -: | ---: | ------------: |
|  5 |   25 |            32 |
| 10 |  100 |         1,024 |
| 20 |  400 |     1,048,576 |
| 30 |  900 | 1,073,741,824 |

This illustrates why exponential-time algorithms can become impractical much sooner.

---

# 10. P and NP

The relationship is:

$$
\boxed{P \subseteq NP}
$$

Why?

If we can **solve** a problem efficiently, then we can certainly **verify** its solution efficiently.

Conceptually:

```text
P
│
├── Efficiently solve
│
└── Therefore efficiently verify
        ↓
       NP
```

---

# 11. Example of Verification

Suppose a polynomial-time algorithm produces:

```text
Shortest path:
A → B → D
```

We can verify the proposed path by checking:

1. The edges exist.
2. The path is valid.
3. Its total cost satisfies the required condition.

Since the solution can be efficiently found and verified, the corresponding decision problem belongs to P and therefore also belongs to NP.

---

# 12. P Problems in Graph Algorithms

Several algorithms studied earlier in DAA belong to polynomial time.

### BFS

$$
O(V+E)
$$

### DFS

$$
O(V+E)
$$

### Kruskal

Typically:

$$
O(E\log E)
$$

### Prim

Depending on implementation, commonly:

$$
O(E\log V)
$$

### Dijkstra

With a binary heap:

$$
O((V+E)\log V)
$$

These are polynomial-time complexities.

# 13. Student Example — BFS

Consider:

```text
A
| \
B  C
|   \
D    E
```

Question:

> Is E reachable from A?

BFS:

```text
Start A
 ↓
B, C
 ↓
D, E
```

E is reached.

Answer:

```text
YES
```

The algorithm solves the problem in polynomial time.

---

# 14. Important Difference: Algorithm vs Problem

Do not confuse:

```text
Problem
```

with:

```text
Algorithm
```

For example:

### Problem

> Is there a path between two vertices?

### Algorithm

> BFS

BFS provides an efficient solution to the problem.

Therefore, the **decision problem** is in P.

---

# 15. Problems with Polynomial Solutions

A problem belongs to P when there exists a polynomial-time algorithm that solves it.

We don't classify a problem based only on one inefficient algorithm.

For example, suppose a problem has:

```text
Algorithm A → O(2ⁿ)
Algorithm B → O(n²)
```

Because Algorithm B solves it in polynomial time, the problem belongs to P.

---

# 16. Problems in P and NP-Complete Problems

The major conceptual distinction is:

```text
P
↓
Known polynomial-time solution
```

while for an NP-Complete problem:

```text
NP-Complete
↓
Solution can be verified in polynomial time
↓
No polynomial-time solution is currently known
```

It is important not to state that NP-Complete problems **cannot** have polynomial-time algorithms. Whether all NP problems can be solved in polynomial time is the famous **P vs NP** question.

---

# 17. P vs NP vs NP-Complete

| Feature                        | P                  | NP                | NP-Complete         |
| ------------------------------ | ------------------ | ----------------- | ------------------- |
| Decision problem               | Yes                | Yes               | Yes                 |
| Polynomial-time solution known | Yes                | Not necessarily   | Not currently known |
| Polynomial-time verification   | Yes                | Yes               | Yes                 |
| NP-hard                        | Not necessarily    | Not necessarily   | Yes                 |
| Example                        | Graph Reachability | Hamiltonian Cycle | Hamiltonian Cycle   |

# 19. Common Mistakes

### Mistake 1

Thinking:

> P means "easy."

Better:

> P means the problem has a polynomial-time algorithm.

---

### Mistake 2

Thinking:

> NP means "Not Polynomial."

Incorrect.

NP means:

> **Nondeterministic Polynomial Time**

and is characterized by polynomial-time verification of proposed solutions.

---

### Mistake 3

Thinking:

> Every exponential algorithm means the problem is not in P.

Incorrect.

A problem may have both an exponential algorithm and a polynomial algorithm.

The classification depends on whether **a polynomial-time algorithm exists**.

---

### Mistake 4

Thinking:

> P and NP are completely separate classes.

Known relationship:

$$
\boxed{P\subseteq NP}
$$
