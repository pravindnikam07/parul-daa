# Unit 6: Backtracking and Branch & Bound

## Topic 6.2 — Introduction to Branch & Bound

## 1. Introduction

**Branch and Bound** is an algorithmic technique used mainly for solving **optimization problems**.

It systematically explores possible solutions by:

* **Branching:** Dividing the problem into smaller choices.
* **Bounding:** Calculating a bound on the best possible solution from a branch.
* **Pruning:** Discarding a branch when it cannot produce a better solution than the current best solution.

### Basic idea

```text
                 Problem
                    |
              ┌─────┴─────┐
            Branch       Branch
             /              \
          Bound            Bound
           /                  \
       Promising            Not promising
          ↓                     X
       Explore                Prune
```

---

# 2. Why Branch and Bound?

Consider an optimization problem where there are many possible solutions.

For example:

```text
              Start
            /       \
           A         B
         /  \       /  \
        C    D     E    F
       / \  / \   / \  / \
      ... ... ... ... ... ...
```

Examining every possible solution can be expensive.

Branch and Bound avoids unnecessary branches by calculating whether a branch can potentially improve the current best solution.

---

# 3. Branching

**Branching** means dividing a problem into multiple subproblems.

For example, in the **0/1 Knapsack problem**, for each item we have two choices:

```text
                 Item
                /    \
            Include  Exclude
```

For the next item:

```text
                 Start
                /     \
             Take     Don't Take
             /           \
          Take           Take
         /                  \
       ...                  ...
```

Each path represents a possible selection of items.

---

# 4. Bounding

A **bound** estimates the best solution that could possibly be obtained from a particular branch.

Suppose the current best profit is:

```text id="1v5g1s"
Best = 100
```

For another branch, suppose the calculated upper bound is:

```text id="1r8k5u"
Bound = 85
```

Since even the best possible solution from this branch can reach only `85`:

```text id="8p6j1h"
85 < 100
```

there is no reason to explore that branch.

Therefore:

```text id="0oj4u0"
Prune branch
```

---

# 5. Branch, Bound and Prune

These three concepts form the foundation.

### Branch

Create possible choices.

```text
Problem
 /    \
A      B
```

### Bound

Calculate the best possible result that can come from each branch.

```text
A → Bound = 120
B → Bound = 80
```

### Prune

If a branch cannot improve the current best result, discard it.

```text
Current Best = 100

A → 120 → Explore
B → 80  → Prune
```

---

# 6. Maximization vs Minimization

The pruning condition depends on the type of optimization problem.

## Maximization Problem

Example:

```text
Maximum Profit
```

If:

```text
Bound ≤ Current Best
```

the branch can be pruned.

### Example

```text
Current Best = 100
Bound = 90
```

Since:

```text
90 ≤ 100
```

prune the branch.

---

## Minimization Problem

Example:

```text
Minimum Cost
```

If:

```text
Bound ≥ Current Best
```

the branch can be pruned.

### Example

```text
Current Best = 50
Bound = 70
```

Since:

```text
70 ≥ 50
```

prune the branch.

---

# 7. State-Space Tree

Branch and Bound commonly represents the search using a **state-space tree**.

For a 0/1 decision:

```text
                   Root
                 /      \
              Include   Exclude
               /          \
           Include       Exclude
             /              \
           ...              ...
```

Each node contains information about a partial solution.

For example:

```text
Node
 ├── Current solution
 ├── Current cost/profit
 ├── Bound
 └── Other problem information
```

---

# 8. Example — 0/1 Knapsack

Consider:

| Item | Weight | Profit |
| ---- | -----: | -----: |
| 1    |      2 |     40 |
| 2    |      3 |     50 |
| 3    |      4 |     65 |

Knapsack capacity:

```text
W = 5
```

For each item:

```text
Include item
       OR
Exclude item
```

Therefore, the search tree starts as:

```text
                 Start
                /     \
            Include   Exclude
             Item 1    Item 1
             /           \
          Item 2        Item 2
          /   \          /   \
       Take  Skip      Take  Skip
```

Branch and Bound calculates an upper bound for each node and avoids branches that cannot improve the current best profit.

The detailed **0/1 Knapsack using Branch and Bound** will be covered separately in the syllabus.

---

# 9. Bound in Knapsack

For the 0/1 Knapsack problem, an upper bound can be estimated using the idea of the **fractional knapsack**.

The fractional solution gives an optimistic maximum profit because it allows taking a fraction of an item.

Since 0/1 Knapsack does not allow fractions:

```text
Fractional solution ≥ 0/1 solution
```

Therefore, the fractional result can be used as an **upper bound**.

Example:

```text
Current best profit = 80
Upper bound = 75
```

The branch can be discarded.

---

# 10. Backtracking vs Branch and Bound

These two techniques both use a state-space tree, but their main purpose is different.

| Feature          | Backtracking            | Branch and Bound       |
| ---------------- | ----------------------- | ---------------------- |
| Main purpose     | Find feasible solutions | Find optimal solution  |
| Main concern     | Constraints             | Objective value        |
| Pruning based on | Constraint violation    | Bound and current best |
| Typical problems | N-Queens                | Optimization problems  |
| Search           | Systematic              | Systematic             |
| Uses bound       | Not necessarily         | Yes                    |

### Easy way to remember

```text
Backtracking
→ "Can this solution still be valid?"

Branch & Bound
→ "Can this branch still produce a better solution?"
```

---

# 11. Example to Understand the Difference

Suppose we need to select items subject to constraints.

### Backtracking

If a branch violates a constraint:

```text
Weight > Capacity
```

we immediately stop exploring it.

```text
Branch
  ↓
Weight exceeds capacity
  ↓
Prune
```

### Branch and Bound

Even if a branch is feasible, we may stop if it cannot beat the current best solution.

```text
Branch
  ↓
Feasible
  ↓
Upper Bound = 70
Current Best = 100
  ↓
70 < 100
  ↓
Prune
```

This is the key difference.

---

# 12. Search Strategies

Branch and Bound can use different strategies for selecting which node to explore next.

Common approaches include:

### FIFO Branch and Bound

Use a **Queue**.

```text
First In → First Out
```

Nodes are explored in a breadth-first manner.

### LIFO Branch and Bound

Use a **Stack**.

```text
Last In → First Out
```

Nodes are explored in a depth-first manner.

### Least-Cost / Best-Bound Branch and Bound

Use a **Priority Queue**.

The most promising node according to its bound is selected first.

For example, for a maximization problem:

```text
Node A → Bound 150
Node B → Bound 110
Node C → Bound 130
```

The algorithm may select:

```text
A → 150
```

first.

---

# 13. General Branch and Bound Algorithm

For a maximization problem:

```text
1. Create the root node.
2. Calculate its bound.
3. Put the root into the list of live nodes.
4. Select a live node.
5. Generate its child nodes.
6. Calculate the bound of each child.
7. If a child can improve the current best:
       Keep the child.
   Otherwise:
       Prune the child.
8. Repeat until no promising live nodes remain.
9. Return the best solution.
```

---

# 14. Important Terms

| Term             | Meaning                                |
| ---------------- | -------------------------------------- |
| Branch           | Divide the problem into subproblems    |
| Bound            | Estimate of the best possible result   |
| Node             | A state/partial solution               |
| Live node        | Node that may still be explored        |
| Dead node        | Node that will not be explored further |
| Incumbent        | Current best known solution            |
| Pruning          | Removing an unpromising branch         |
| State-space tree | Tree representing possible decisions   |

# 15. Live and Dead Nodes

Consider:

```text
                Root
              /      \
             A        B
           /   \      |
          C     D     E
```

Suppose:

```text
C → promising
D → cannot improve solution
E → promising
```

Then:

```text
C = Live
D = Dead
E = Live
```

A **live node** can still lead to a better solution.

A **dead node** is not worth exploring further.

# 16. Java — Basic Branch and Bound Structure

A simple generic structure can be represented using a priority queue.

```java id="t7xj9w"
import java.util.*;

class Node {
    int level;
    int profit;
    int weight;
    double bound;

    Node(int level, int profit, int weight, double bound) {
        this.level = level;
        this.profit = profit;
        this.weight = weight;
        this.bound = bound;
    }
}

public class BranchAndBoundExample {

    public static void main(String[] args) {

        PriorityQueue<Node> pq =
                new PriorityQueue<>(
                    (a, b) -> Double.compare(b.bound, a.bound)
                );

        Node root = new Node(0, 0, 0, 100);

        pq.add(root);

        while (!pq.isEmpty()) {

            Node current = pq.poll();

            System.out.println(
                "Level: " + current.level +
                ", Profit: " + current.profit +
                ", Weight: " + current.weight +
                ", Bound: " + current.bound
            );
        }
    }
}
```

This demonstrates the basic structure:

```text
Priority Queue
      ↓
Select promising node
      ↓
Branch
      ↓
Calculate bounds
      ↓
Prune unpromising nodes
```

A complete knapsack implementation requires a problem-specific bound calculation.

# 17. C++ — Basic Branch and Bound Structure

```cpp id="4t9j2a"
#include <iostream>
#include <queue>
using namespace std;

struct Node {
    int level;
    int profit;
    int weight;
    double bound;
};

struct Compare {
    bool operator()(Node a, Node b) {
        return a.bound < b.bound;
    }
};

int main() {

    priority_queue<Node, vector<Node>, Compare> pq;

    Node root = {0, 0, 0, 100};

    pq.push(root);

    while (!pq.empty()) {

        Node current = pq.top();
        pq.pop();

        cout << "Level: " << current.level
             << ", Profit: " << current.profit
             << ", Weight: " << current.weight
             << ", Bound: " << current.bound
             << endl;
    }

    return 0;
}
```

Again, this demonstrates the **Branch and Bound framework**, while the actual bound calculation depends on the optimization problem.

# 19. Branch and Bound for TSP

In the **Travelling Salesman Problem**, the objective is to find a minimum-cost tour that:

* Visits every city exactly once.
* Returns to the starting city.

A state-space tree can represent partial tours:

```text
                 A
              /  |  \
             B   C   D
            / \  ...
           C   D
          ...
```

For every partial tour, Branch and Bound calculates a **lower bound on the possible final tour cost**.

For a minimization problem:

```text
Lower Bound ≥ Current Best
```

means the branch cannot produce a better solution, so it can be pruned.

The detailed TSP algorithm will be covered later.

# 20. Complexity

Branch and Bound does **not guarantee polynomial time** for the problems in this syllabus.

The worst-case search can still be exponential or factorial.

However, bounding and pruning can significantly reduce the number of states explored in practice.

The effectiveness depends on:

* Quality of the bound
* Problem structure
* Number of branches
* Search strategy

# 21. Important Exam Concept

### Why is Branch and Bound better than simple brute force?

Not because it changes every problem's worst-case complexity.

Its advantage is that it **avoids exploring branches that cannot lead to an improved solution**.

```text
Brute Force:

Explore → Explore → Explore → Explore → ...
```

```text
Branch & Bound:

Explore
   ↓
Calculate Bound
   ↓
Promising?
 ├── Yes → Explore
 └── No  → Prune
```

# 22. Common Mistakes

### Mistake 1: Confusing bound with the current solution

The **current solution value** and the **bound** are different.

```text
Current Profit = 80
Upper Bound = 120
```

`120` is only an estimate of the maximum achievable profit from that branch.

---

### Mistake 2: Using the wrong pruning condition

For maximization:

```text
Bound ≤ Best
→ Prune
```

For minimization:

```text
Bound ≥ Best
→ Prune
```

---

### Mistake 3: Assuming Branch and Bound always runs quickly

Branch and Bound can still have exponential or factorial worst-case behavior.

Its efficiency depends heavily on how effectively branches can be pruned.
