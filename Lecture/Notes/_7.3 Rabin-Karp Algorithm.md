# Unit 7: String Matching & NP Completeness

## Topic 7.3 — Rabin-Karp Algorithm

## 1. Introduction

The **Rabin-Karp algorithm** is a string-matching algorithm that uses **hashing** to find a pattern inside a text.

Instead of directly comparing the pattern with every substring character by character, it:

1. Calculates a hash value for the pattern.
2. Calculates a hash value for each text window of the same length.
3. Compares the hash values.
4. If the hash values match, compares the actual characters to confirm the match.

### Basic idea

```text
Pattern
   ↓
Calculate Hash
   ↓
Compare with text-window hash
   ↓
Hash match?
  /      \
No       Yes
 |         |
Shift    Verify characters
          |
       Match found
```

---

# 2. Why Hashing?

Consider:

```text
Text    = "ABABCABAB"
Pattern = "ABAB"
```

The pattern length is `4`.

We examine windows of length `4`:

```text
ABAB
BABC
ABCA
BCAB
CABA
ABAB
```

Instead of immediately comparing all four characters in every window, Rabin-Karp first compares their hash values.

```text
Hash("ABAB") == Hash("ABAB")
        ↓
    Possible match
        ↓
Compare actual characters
```

---

# 3. Important Concept: Hash Value

A **hash function** converts a string into a numerical value.

For example, for demonstration:

```text
A = 1
B = 2
C = 3
```

Then:

```text
AB
```

could be represented numerically as:

```text
1 2
```

In practice, Rabin-Karp uses a polynomial rolling hash rather than simply adding character values.

---

# 4. Polynomial Hash

For a string:

```text
P = p0 p1 p2 ... pm-1
```

a polynomial hash can be represented as:

$$
H(P)=
(p_0b^{m-1}+p_1b^{m-2}+\cdots+p_{m-1})\bmod q
$$

where:

- `b` = base
- `q` = modulus
- `pᵢ` = numerical value of a character

The modulus keeps the hash value within a manageable range.

---

# 5. Why Rolling Hash?

The important feature of Rabin-Karp is the **rolling hash**.

Suppose:

```text
Text = "ABCDE"
Pattern length = 3
```

First window:

```text
ABC
```

Next window:

```text
BCD
```

We don't need to calculate the hash of `BCD` completely from scratch.

We:

1. Remove `A`.
2. Shift the remaining characters.
3. Add `D`.

```text
ABC
 ↓
remove A
 ↓
BC
 ↓
add D
 ↓
BCD
```

This allows the next hash to be calculated efficiently.

---

# 6. Rolling Hash Formula

Suppose the current window has hash `H`.

To move the window one position:

### Step 1 — Remove the first character

### Step 2 — Shift the remaining value

### Step 3 — Add the new character

A common rolling-hash formula is:

$$
H_{next}
=
((H-old\times h)\times b+new)\bmod q
$$

where:

$$
h=b^{m-1}\bmod q
$$

The exact implementation may vary depending on the chosen character encoding and hash convention.

---

# 7. Example

Consider:

```text
Text    = "ABCD"
Pattern = "BC"
```

Pattern length:

```text
m = 2
```

Windows:

```text
AB
BC
CD
```

We calculate:

```text
Hash(Pattern) = Hash(BC)
```

Then compare:

```text
Hash(AB)
Hash(BC)
Hash(CD)
```

When:

```text
Hash(BC) == Hash(Pattern)
```

we verify:

```text
BC == BC
```

Therefore, the pattern is found at index `1`.

---

# 8. Hash Collision

A very important concept in Rabin-Karp is a **hash collision**.

A collision occurs when two different strings have the same hash value.

For example:

```text
Hash("AB") = 15
Hash("CD") = 15
```

Even though:

```text
AB ≠ CD
```

their hash values are equal.

Therefore:

> **A hash match does not necessarily mean that the strings are equal.**

The actual characters must be compared to confirm the match.

---

# 9. Why Character Verification Is Necessary

Suppose:

```text
Pattern = "AB"
Window  = "CD"
```

and:

```text
Hash("AB") == Hash("CD")
```

This is a collision.

Rabin-Karp therefore performs:

```text
Hash match
    ↓
Compare actual strings
    ↓
Different
    ↓
Not a match
```

This prevents false matches caused by collisions.

---

# 10. Rabin-Karp Algorithm

```text
RabinKarp(T, P)

n = length(T)
m = length(P)

Calculate hash(P)
Calculate hash(T[0 ... m-1])

for i = 0 to n-m:

    if hash(P) == hash(current window):

        compare P with current window

        if equal:
            report match

    calculate hash of next window
```

---

# 11. Java Implementation

```java id="u1pxl4"
public class RabinKarp {

    static final int BASE = 256;
    static final int PRIME = 101;

    static void search(String text, String pattern) {

        int n = text.length();
        int m = pattern.length();

        if (m > n) {
            return;
        }

        int patternHash = 0;
        int windowHash = 0;
        int h = 1;

        // h = BASE^(m-1) % PRIME
        for (int i = 0; i < m - 1; i++) {
            h = (h * BASE) % PRIME;
        }

        // Calculate initial hashes
        for (int i = 0; i < m; i++) {

            patternHash =
                (BASE * patternHash +
                 pattern.charAt(i)) % PRIME;

            windowHash =
                (BASE * windowHash +
                 text.charAt(i)) % PRIME;
        }

        for (int i = 0; i <= n - m; i++) {

            // Hash values match
            if (patternHash == windowHash) {

                int j = 0;

                while (j < m &&
                       text.charAt(i + j) ==
                       pattern.charAt(j)) {
                    j++;
                }

                if (j == m) {
                    System.out.println(
                        "Pattern found at index " + i
                    );
                }
            }

            // Calculate next window hash
            if (i < n - m) {

                windowHash =
                    (BASE *
                     (windowHash -
                      text.charAt(i) * h)
                     + text.charAt(i + m))
                    % PRIME;

                if (windowHash < 0) {
                    windowHash += PRIME;
                }
            }
        }
    }

    public static void main(String[] args) {

        String text = "ABABCABAB";
        String pattern = "ABAB";

        search(text, pattern);
    }
}
```

### Output

```text id="i3k7xy"
Pattern found at index 0
Pattern found at index 5
```

# 12. C++ Implementation

```cpp id="xk9gob"
#include <iostream>
#include <string>
using namespace std;

const int BASE = 256;
const int PRIME = 101;

void searchPattern(string text, string pattern) {

    int n = text.length();
    int m = pattern.length();

    if (m > n) {
        return;
    }

    int patternHash = 0;
    int windowHash = 0;
    int h = 1;

    // h = BASE^(m-1) % PRIME
    for (int i = 0; i < m - 1; i++) {
        h = (h * BASE) % PRIME;
    }

    // Initial hash values
    for (int i = 0; i < m; i++) {

        patternHash =
            (BASE * patternHash +
             pattern[i]) % PRIME;

        windowHash =
            (BASE * windowHash +
             text[i]) % PRIME;
    }

    for (int i = 0; i <= n - m; i++) {

        if (patternHash == windowHash) {

            int j = 0;

            while (j < m &&
                   text[i + j] == pattern[j]) {
                j++;
            }

            if (j == m) {
                cout << "Pattern found at index "
                     << i << endl;
            }
        }

        // Calculate next window hash
        if (i < n - m) {

            windowHash =
                (BASE *
                 (windowHash -
                  text[i] * h)
                 + text[i + m])
                % PRIME;

            if (windowHash < 0) {
                windowHash += PRIME;
            }
        }
    }
}

int main() {

    string text = "ABABCABAB";
    string pattern = "ABAB";

    searchPattern(text, pattern);

    return 0;
}
```


```text
ABC
 ↓
remove A
 ↓

add A
 ↓

```

```text
Hash(BCA) != Hash(ABC)
```

# 15. Time Complexity

### Average / Expected Case

With a good hash function and suitable modulus:

$$
\boxed{O(n+m)}
$$

for a single pattern, in the expected/typical analysis.

### Worst Case

If many hash collisions occur, character verification may repeatedly take place.

Therefore:

$$
\boxed{O(nm)}
$$

### Space Complexity

For a single pattern:

$$
\boxed{O(1)}
$$

additional space, excluding the input.

---

# 16. Why Rabin-Karp Can Be Useful

The major advantage is that it can compare **hash values quickly**.

It is especially useful when searching for:

- Multiple patterns
- Matching substrings
- Similar sequences

For multiple patterns of the same length, their hash values can be organized so that text windows are compared against the set of pattern hashes.

---

# 17. Rabin-Karp vs Naive

| Feature                       | Naive                | Rabin-Karp   |
| ----------------------------- | -------------------- | ------------ |
| Main technique                | Character comparison | Hashing      |
| Preprocessing                 | No                   | Pattern hash |
| Window processing             | Direct comparison    | Rolling hash |
| Average/expected              | `O(nm)`              | `O(n+m)`     |
| Worst case                    | `O(nm)`              | `O(nm)`      |
| Collision issue               | No                   | Yes          |
| Verification after hash match | Not applicable       | Required     |

---

# 18. Important Concepts to Remember

### 1. Hash

Numerical representation of a string.

### 2. Rolling Hash

Efficiently calculates the hash of the next text window from the current window.

### 3. Hash Collision

Different strings can have the same hash.

### 4. Verification

Actual character comparison confirms whether a hash match is a real match.

### 5. Modulus

A prime modulus is commonly used to keep hash values manageable and reduce collisions.

---

# 19. Common Mistakes

### Mistake 1 — Assuming equal hashes mean equal strings

Incorrect:

```text
Hash(P) == Hash(W)
→ Definitely a match
```

Correct:

```text
Hash(P) == Hash(W)
        ↓
Verify characters
        ↓
Actual match
```

---

### Mistake 2 — Forgetting negative hash values

During rolling hash calculation, subtraction can produce a negative value.

Therefore:

```java
if (windowHash < 0) {
    windowHash += PRIME;
}
```

is required in this implementation.

---

### Mistake 3 — Incorrect rolling hash

The outgoing character must be removed using:

$$
old \times b^{m-1}
$$

before adding the new character.

---

### Mistake 4 — Forgetting the last window

The loop must include:

```text
i <= n - m
```
