# 1. Real-World Motivation

Imagine you own a cargo company.

A truck can carry **50 kg** of goods.

You have several packages:

| Package | Weight (kg) | Value ($) |
| ------- | ----------: | --------: |
| Gold    |          10 |       600 |
| Silver  |          20 |       500 |
| Copper  |          30 |       400 |

Your goal:

- Maximize total value.
- Truck capacity cannot exceed **50 kg**.

Unlike many problems, **you are allowed to divide a package**.

For example, if only 10 kg capacity remains, you can load **10 kg out of a 30 kg package**.

This is the **Fractional Knapsack Problem**.

# 3. What is the Fractional Knapsack Problem?

## Definition

Given:

- A knapsack with limited capacity.
- Items with weights and profits.
- Items can be divided into fractions.

Find the maximum possible profit.

---


# 4. Why Greedy Works Here

Suppose two items:

| Item | Weight | Profit |
| ---- | -----: | -----: |
| A    |     10 |    600 |
| B    |     10 |    300 |

Which should we choose first?

Obviously

```text
A
```

because it gives more profit.

Now consider:

| Item | Weight | Profit |
| ---- | -----: | -----: |
| A    |     20 |    600 |
| B    |     10 |    400 |

Now comparing only total profit is misleading.

Instead,

calculate

```text
Profit per Unit Weight
```

# 5. Profit-to-Weight Ratio

Formula

```text
Ratio = Profit / Weight
```

---

Example

| Item | Profit | Weight | Ratio |
| ---- | -----: | -----: | ----: |
| A    |    600 |     10 |    60 |
| B    |    500 |     20 |    25 |
| C    |    400 |     30 | 13.33 |

Higher ratio means

More profit for every kilogram.

---

# Important Rule

Always choose the item having the **highest profit-to-weight ratio** first.

This is the Greedy choice.

---

# 6. Algorithm

Step 1

Calculate

```text
Profit / Weight
```

for every item.

---

Step 2

Sort all items in decreasing order of ratio.

---

Step 3

Pick the highest ratio item completely.

---

Step 4

Repeat.

---

Step 5

If remaining capacity is smaller than the item's weight,

take only the required fraction.

Stop.

# 11. Why Greedy is Optimal

The Fractional Knapsack Problem satisfies:

- Greedy Choice Property
- Optimal Substructure

Because items are divisible,

choosing the highest ratio first **can never reduce** the optimal answer.

This is why Greedy always produces the optimal solution.

# 12. Fractional vs 0/1 Knapsack

This is the most important theory question.

| Fractional Knapsack           | 0/1 Knapsack                                   |
| ----------------------------- | ---------------------------------------------- |
| Items can be divided          | Items cannot be divided                        |
| Greedy gives optimal solution | Greedy does **not** guarantee optimal solution |
| Solved using Greedy           | Solved using Dynamic Programming               |
| Easier                        | More difficult                                 |
| Time Complexity: O(n log n)   | DP Time Complexity: O(n × W)                   |

# 13. Java Implementation

```java
import java.util.*;

class Item {

    int weight;
    int profit;
    double ratio;

    Item(int weight, int profit) {

        this.weight = weight;
        this.profit = profit;
        this.ratio = (double) profit / weight;
    }
}

public class FractionalKnapsack {

    public static void main(String[] args) {

        int capacity = 50;

        Item[] items = {
                new Item(10,600),
                new Item(20,500),
                new Item(30,400)
        };

        Arrays.sort(items,
                (a,b)->Double.compare(b.ratio,a.ratio));

        double totalProfit=0;

        for(Item item:items){

            if(capacity>=item.weight){

                capacity-=item.weight;

                totalProfit+=item.profit;
            }
            else{

                totalProfit+=item.ratio*capacity;

                capacity=0;

                break;
            }
        }

        System.out.println("Maximum Profit = "+totalProfit);
    }
}
```

**Output**

```text
Maximum Profit = 1366.67
```

# 14. C++ Implementation

```cpp
#include<iostream>
#include<vector>
#include<algorithm>

using namespace std;

struct Item{

    int weight;
    int profit;
    double ratio;
};

bool compare(Item a,Item b){

    return a.ratio>b.ratio;
}

int main(){

    int capacity=50;

    vector<Item> items={
        {10,600,60},
        {20,500,25},
        {30,400,13.33}
    };

    sort(items.begin(),items.end(),compare);

    double totalProfit=0;

    for(auto item:items){

        if(capacity>=item.weight){

            capacity-=item.weight;

            totalProfit+=item.profit;
        }
        else{

            totalProfit+=capacity*item.ratio;

            break;
        }
    }

    cout<<"Maximum Profit = "<<totalProfit;

    return 0;
}
```

> **Teaching Note:** For production-quality code, compute the ratio inside the constructor or before sorting instead of hardcoding values. This example keeps the focus on the greedy logic.

- Low memory usage.

---

# 18. Limitations

- Works only when items are divisible.
- Cannot solve the 0/1 Knapsack Problem.
- Assumes proportional profit (taking half the weight gives half the profit).

---

# 19. Common Mistakes

- Sorting by profit instead of profit-to-weight ratio.
- Forgetting to compute the ratio as a floating-point value.
- Taking an entire item when only a fraction fits.
- Confusing Fractional Knapsack with 0/1 Knapsack.

---

# 20. Best Practices

- Always compute the ratio using floating-point division.
- Sort items in **descending** order of ratio.
- After taking a fraction of an item, stop because the knapsack is full.
- Mention in exams that the greedy approach works because the problem satisfies the **Greedy Choice Property**.

# 25. Summary

- The **Fractional Knapsack Problem** is an optimization problem where items **can be divided** into smaller parts.
- The greedy strategy is to always choose the item with the **highest profit-to-weight ratio**.
- If an entire item cannot fit into the remaining capacity, only the required **fraction** is taken.
- The algorithm is optimal because the problem satisfies the **Greedy Choice Property** and **Optimal Substructure**.
- The overall time complexity is **O(n log n)** due to sorting.
- Unlike the **0/1 Knapsack Problem**, the Fractional Knapsack Problem is efficiently solved using a **Greedy Algorithm**.
