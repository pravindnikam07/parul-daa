# 1. Introduction

Both **Kruskal's Algorithm** and **Prim's Algorithm** are **Greedy Algorithms** used to find the **Minimum Spanning Tree (MST)** of a **connected, undirected, weighted graph**.

Although both produce the same final result (an MST), they use **different strategies**.

---

# 2. The Core Philosophy

## Kruskal's Thinking

Imagine you have a basket containing **all roads** in a country.

You sort them from cheapest to most expensive.

Now start selecting the cheapest roads one by one.

If a road creates a cycle, ignore it.

Continue until all cities are connected.

> **Focus:** Edges

---

## Prim's Thinking

Imagine you are standing in one city.

From there, you expand your road network gradually.

Every time, you connect the nearest unvisited city.

Continue until every city is connected.

> **Focus:** Vertices and the growing tree

# 5. Detailed Comparison Table

| Feature              | Kruskal's Algorithm                           | Prim's Algorithm                                          |
| -------------------- | --------------------------------------------- | --------------------------------------------------------- |
| Basic Strategy       | Select the globally smallest edge             | Expand one tree from a starting vertex                    |
| Starts With          | Sorted list of edges                          | Any vertex                                                |
| Focus                | Edges                                         | Vertices                                                  |
| Cycle Detection      | Required                                      | Not explicitly required (visited vertices prevent cycles) |
| Data Structure       | Disjoint Set (Union-Find)                     | Priority Queue (Min Heap)                                 |
| Edge Sorting         | Required                                      | Not required                                              |
| Intermediate Result  | Forest (multiple trees) that gradually merges | One connected tree that gradually grows                   |
| Suitable for         | Sparse graphs                                 | Dense graphs                                              |
| Graph Representation | Edge List                                     | Adjacency List / Matrix                                   |
| Typical Complexity   | O(E log E)                                    | O(E log V) using Min Heap                                 |
| Can Start Anywhere?  | No (depends on sorted edges)                  | Yes                                                       |
| Greedy Choice        | Globally smallest valid edge                  | Smallest edge leaving the current MST                     |

# 7. Why Kruskal Needs Union-Find

Suppose we have

```text
A------B

|

|

C
```

If we add

```text
B------C
```

A cycle forms.

Kruskal must detect this.

Hence,

it uses **Union-Find**.

---

# 8. Why Prim Doesn't Need Union-Find

Prim always selects

an edge

from

Visited

↓

Unvisited

Since it never joins two already visited vertices,

cycles are naturally avoided.

Instead,

it only needs

```text
Visited[]

Priority Queue
```

# 13. Choosing the Right Algorithm

| Situation                                              | Preferred Algorithm |
| ------------------------------------------------------ | ------------------- |
| Road network with relatively few roads                 | Kruskal             |
| Computer network where most devices are interconnected | Prim                |
| Graph represented as an edge list                      | Kruskal             |
| Graph represented as an adjacency list                 | Prim                |
| Easy conceptual implementation                         | Kruskal             |
| Existing priority queue support                        | Prim                |

---

# 14. Common Mistakes

- Thinking Prim also sorts all edges.
- Believing Kruskal starts from a specific vertex.
- Assuming both algorithms require Union-Find.
- Confusing **visited vertices** in Prim with **connected components** in Kruskal.
- Using the wrong graph representation for the chosen algorithm.

---

# 15. Best Practices

- Use **Kruskal's Algorithm** when the graph is sparse or naturally available as an edge list.
- Use **Prim's Algorithm** when the graph is dense or stored as an adjacency list.
- In interviews, always justify your choice based on graph density and available data structures.
- Understand the algorithm's intuition rather than memorizing comparison tables.

# 20. Summary

- Both **Kruskal's** and **Prim's** algorithms are greedy methods for finding a **Minimum Spanning Tree (MST)**.
- **Kruskal's Algorithm** processes edges in increasing order of weight, using **Union-Find** to avoid cycles.
- **Prim's Algorithm** starts from any vertex and repeatedly expands the current tree using the **minimum edge** to an unvisited vertex, typically with a **Priority Queue**.
- Kruskal is generally preferred for **sparse graphs**, while Prim is often more efficient for **dense graphs**.
- Although their strategies differ, both algorithms produce an MST with the **minimum total weight** for a connected, undirected, weighted graph.
