# 1. Real-World Motivation

Imagine you are the manager of a conference hall.

Many organizations want to book the hall.

Unfortunately,

only **one event can be conducted at a time**.

Your objective is:

> **Schedule the maximum number of non-overlapping events.**

Example:

| Event           | Start | Finish |
| --------------- | ----: | -----: |
| Seminar         |     9 |     11 |
| Workshop        |    10 |     12 |
| Placement Drive |    11 |      1 |
| Alumni Meet     |     1 |      3 |

Since two events cannot occur simultaneously, you need to choose the best schedule.

This is the **Activity Selection Problem**.

---

# 2. Everyday Analogy

Imagine a doctor in a clinic.

Many patients have appointments.

The doctor can treat **only one patient at a time**.

Goal:

Treat the **maximum number of patients**.

The best strategy is to finish one appointment as early as possible so more appointments can fit later.

# 3. Problem Statement

Given:

- **n** activities
- Each activity has:

  - Start Time
  - Finish Time

Find the **maximum number of mutually compatible (non-overlapping)** activities.

---

# Example

| Activity | Start | Finish |
| -------- | ----: | -----: |
| A1       |     1 |      4 |
| A2       |     3 |      5 |
| A3       |     0 |      6 |
| A4       |     5 |      7 |
| A5       |     8 |      9 |
| A6       |     5 |      9 |

Goal:

Select the largest set of non-overlapping activities.

# 4. Why Greedy?

Suppose the first selected activity finishes very late.

```text
A ----------- B
```

Then very little time remains for future activities.

Instead,

select the activity that finishes earliest.

```text
A ---- B
```

Now many future activities can still fit.

This is the **Greedy Choice**.

---

# 5. Greedy Strategy

> **Always select the activity that finishes first among the remaining compatible activities.**

This strategy leaves the maximum remaining time for future activities.

---

# 6. Why Not Choose Earliest Start Time?

Consider:

| Activity | Start | Finish |
| -------- | ----: | -----: |
| A        |     1 |     10 |
| B        |     2 |      3 |
| C        |     3 |      4 |
| D        |     4 |      5 |

If we choose the earliest starting activity:

```text
A (1-10)
```

Only one activity is selected.

But choosing

```text
B → C → D
```

allows three activities.

Hence,

**Earliest Start Time is NOT optimal.**

---

# 7. Why Not Choose Shortest Duration?

Example:

| Activity | Start | Finish | Duration |
| -------- | ----: | -----: | -------: |
| A        |     1 |      4 |        3 |
| B        |     4 |      5 |        1 |
| C        |     2 |      3 |        1 |

Choosing the shortest duration first may block better combinations.

Only the **Earliest Finish Time** strategy guarantees an optimal solution.

---

# 8. Algorithm

### Step 1

Sort all activities by **finish time**.

---

### Step 2

Select the first activity.

---

### Step 3

For every remaining activity,

If

```text
Start Time ≥ Finish Time of Last Selected Activity
```

select it.

Otherwise,

skip it.

---

### Step 4

Repeat until all activities are processed.

---

# 9. Pseudocode

```text
Sort activities by finish time

Select first activity

lastFinish = finish(first)

For each remaining activity

    if start >= lastFinish

         Select activity

         lastFinish = finish

Return selected activities
```

# 12. Why Earliest Finish Time Works

Suppose two compatible activities are available:

| Activity | Finish |
| -------- | -----: |
| A        |      5 |
| B        |      8 |

If we choose **A**, more time remains for future activities.

If we choose **B**, we lose the opportunity to schedule activities between time 5 and 8.

Therefore,

choosing the earliest finishing activity always leaves the maximum flexibility.

This is the **Greedy Choice Property**.

---

# 13. Proof (Intuitive)

Suppose an optimal schedule does **not** start with the earliest finishing activity.

Replace its first activity with the earliest finishing one.

Since the replacement finishes earlier (or at the same time),

all remaining activities still fit.

Thus,

the new schedule contains the same number of activities.

Therefore,

an optimal solution always exists that starts with the earliest finishing activity.

Hence,

the greedy strategy is optimal.

# 14. Java Implementation

```java
import java.util.*;

class Activity {
    int start;
    int finish;

    Activity(int start, int finish) {
        this.start = start;
        this.finish = finish;
    }
}

public class ActivitySelection {

    public static void main(String[] args) {

        Activity[] activities = {
            new Activity(1,4),
            new Activity(3,5),
            new Activity(0,6),
            new Activity(5,7),
            new Activity(8,9),
            new Activity(5,9)
        };

        Arrays.sort(activities,
            Comparator.comparingInt(a -> a.finish));

        System.out.println("Selected Activities:");

        int lastFinish = activities[0].finish;

        System.out.println("(" + activities[0].start +
                           "," + activities[0].finish + ")");

        for(int i=1;i<activities.length;i++){

            if(activities[i].start >= lastFinish){

                System.out.println("(" +
                        activities[i].start +
                        "," +
                        activities[i].finish + ")");

                lastFinish = activities[i].finish;
            }
        }
    }
}
```

# 15. C++ Implementation

```cpp
#include<iostream>
#include<vector>
#include<algorithm>

using namespace std;

struct Activity{

    int start;
    int finish;
};

bool compare(Activity a,Activity b){

    return a.finish<b.finish;
}

int main(){

    vector<Activity> activities={
        {1,4},
        {3,5},
        {0,6},
        {5,7},
        {8,9},
        {5,9}
    };

    sort(activities.begin(),
         activities.end(),
         compare);

    cout<<"Selected Activities\n";

    int lastFinish=activities[0].finish;

    cout<<"("<<activities[0].start
        <<","<<activities[0].finish<<")\n";

    for(int i=1;i<activities.size();i++){

        if(activities[i].start>=lastFinish){

            cout<<"("
                <<activities[i].start
                <<","
                <<activities[i].finish
                <<")\n";

            lastFinish=activities[i].finish;
        }
    }

    return 0;
}
```

# 16. Time Complexity

| Step                | Complexity |
| ------------------- | ---------: |
| Sort Activities     | O(n log n) |


# 18. Advantages

- Very efficient.
- Easy to implement.
- Always produces the optimal solution.
- Requires minimal extra memory.

---

# 19. Limitations

- Works only for the **unweighted** version of the problem.
- If activities have different profits or priorities, this greedy approach is not sufficient.
- Assumes only one activity can be performed at a time.

---

# 20. Common Mistakes

- Sorting by start time instead of finish time.
- Forgetting to update the finish time after selecting an activity.
- Using `>` instead of `>=` when checking compatibility (activities that start exactly when the previous one finishes are compatible).
- Assuming shortest duration always gives the optimal answer.

---

# 21. Best Practices

- Always sort by **finish time** in ascending order.
- Clearly distinguish between **selected** and **rejected** activities during dry runs.
- Use a timeline diagram to help visualize overlapping activities.
- Mention the **Greedy Choice Property** in theory answers.

# 27. Summary

- The **Activity Selection Problem** aims to schedule the **maximum number of non-overlapping activities**.
- The optimal greedy strategy is to **always choose the activity with the earliest finish time**.
- Activities are first sorted by **finish time**, then selected if they are compatible with the previously chosen activity.
- The algorithm is optimal because it satisfies the **Greedy Choice Property** and **Optimal Substructure**.
- The overall time complexity is **O(n log n)** due to sorting, or **O(n)** if the activities are already sorted.
