# 3. What is Dynamic Programming?

## Definition

Dynamic Programming (DP) is an algorithmic technique used to solve optimization and counting problems by:

* Breaking a problem into smaller subproblems.
* Solving each subproblem only once.
* Storing the result.
* Reusing the stored result whenever needed.

---

# Simple Definition for Exams

> Dynamic Programming is an optimization technique that stores the solutions of previously solved subproblems to avoid repeated computation.

---

# 4. Why Dynamic Programming?

Suppose we compute

```text
Fibonacci(6)
```

Recursive Tree

```text
                    F(6)
                  /      \
               F(5)      F(4)
              /   \      /   \
           F(4)  F(3) F(3) F(2)
          /   \   / \   / \
       F(3)F(2)...
```

Observe carefully.

```text
F(4)
```

is solved multiple times.

```text
F(3)
```

is solved even more times.

This unnecessary repetition makes recursion slow.

Dynamic Programming stores these results.

Instead of

```text

↓

```

DP performs

```text

↓

Store

↓

Reuse
```

# 6. Two Conditions Required for DP

A problem can be solved using Dynamic Programming **only if it satisfies both conditions**:

## 1. Optimal Substructure

The optimal solution of the original problem can be constructed from the optimal solutions of its smaller subproblems.

---

### Example

Shortest path

```text
A → D
```

Suppose the shortest path is

```text
A → B → C → D
```

Then

```text
A → C
```

must also be the shortest path.

Otherwise,

the entire path cannot be optimal.

This property is called

> **Optimal Substructure**

---

## 2. Overlapping Subproblems

The same subproblem appears repeatedly.

Example

```text
Fibonacci(6)
```

computes

```text
Fibonacci(4)
```

many times.

DP stores

```text
Fibonacci(4)
```

once.

---

With DP

# 7. Principle of Optimality

This is the foundation of Dynamic Programming.

## Definition

> **An optimal solution to a problem is composed of optimal solutions to its subproblems.**

This principle was introduced by **Richard Bellman**, the inventor of Dynamic Programming.

---

### Everyday Example

Suppose you are traveling from:

```text
Ahmedabad

↓

Vadodara

↓

Surat

↓

Mumbai
```

If the overall route is the shortest,

then:

* Ahmedabad → Surat must also be shortest.
* Vadodara → Mumbai must also be shortest.

Otherwise,

the whole journey cannot be optimal.

# 8. Dynamic Programming vs Greedy

This is one of the most important comparison questions.

| Dynamic Programming                                       | Greedy Algorithm                            |
| --------------------------------------------------------- | ------------------------------------------- |
| Considers many possible solutions                         | Chooses the locally best solution           |
| Stores previous results                                   | Does not store results                      |
| Usually guarantees the optimal solution (when applicable) | May or may not produce the optimal solution |
| Often slower than Greedy                                  | Usually faster                              |
| Uses recursion or iteration with memory                   | Makes one decision at a time                |
| Examples: 0/1 Knapsack, LCS                               | Examples: Prim, Kruskal, Dijkstra, Huffman  |

---

# 9. Dynamic Programming vs Divide & Conquer

| Divide & Conquer            | Dynamic Programming             |
| --------------------------- | ------------------------------- |
| Subproblems are independent | Subproblems overlap             |
| Results are not stored      | Results are stored              |
| Recursive approach          | Recursive or iterative approach |
| Example: Merge Sort         | Example: Fibonacci DP           |

---

# 10. Memoization (Top-Down DP)

Memoization uses recursion.

Whenever a function is called,

first check whether the answer already exists.

If yes,

reuse it.

Otherwise,

compute and store it.

---

### Example

```text
fib(5)

↓

Needs fib(4)

↓

Needs fib(3)

↓

Store answers

↓

Reuse later
```

---

# 11. Tabulation (Bottom-Up DP)

Instead of recursion,

start from the smallest subproblem.

Example

```text
fib(0)=0

fib(1)=1

fib(2)=1

fib(3)=2

fib(4)=3

fib(5)=5
```

Every answer is built from previous answers.

No recursion is needed.

---

# 12. Memoization vs Tabulation

| Memoization                      | Tabulation             |
| -------------------------------- | ---------------------- |
| Top-Down                         | Bottom-Up              |
| Uses recursion                   | Uses iteration         |
| Easier to write                  | Usually faster         |
| Recursive call stack required    | No recursion stack     |
| Solves only required subproblems | Solves all subproblems |

# 15. Java Implementation (Memoization)

```java
import java.util.Arrays;

public class FibonacciMemo {

    static int[] dp = new int[100];

    static int fib(int n){

        if(n<=1)
            return n;

        if(dp[n]!=-1)
            return dp[n];

        dp[n]=fib(n-1)+fib(n-2);

        return dp[n];
    }

    public static void main(String[] args){

        Arrays.fill(dp,-1);

        System.out.println(fib(6));
    }
}
```

---

# 16. Java Implementation (Tabulation)

```java
public class FibonacciTabulation {

    public static void main(String[] args){

        int n=6;

        int[] dp=new int[n+1];

        dp[0]=0;

        dp[1]=1;

        for(int i=2;i<=n;i++){

            dp[i]=dp[i-1]+dp[i-2];
        }

        System.out.println(dp[n]);
    }
}
```

# 21. Advantages

* Eliminates repeated computation.
* Produces optimal solutions for many optimization problems.
* Can significantly reduce execution time.
* Applicable to a wide variety of real-world problems.

---

# 22. Limitations

* Uses additional memory to store intermediate results.
* Not every problem can be solved using DP.
* Identifying states and transitions can be challenging.

---

# 23. Common Mistakes

* Applying DP to problems without overlapping subproblems.
* Forgetting to initialize the DP table correctly.
* Confusing Memoization with Tabulation.
* Not identifying the correct state transition.
* Assuming every optimization problem requires DP.

---

# 24. Best Practices (DP Problem Solving Framework)

Whenever you solve a DP problem, follow these steps:

1. **Identify the State**

   * What uniquely defines a subproblem?

2. **Define the Recurrence Relation**

   * How is the current state derived from previous states?

3. **Identify Base Cases**

   * What are the simplest subproblems?

4. **Choose an Approach**

   * Memoization (Top-Down) or Tabulation (Bottom-Up)

5. **Optimize Space (if possible)**

   * Replace arrays with variables when only recent states are needed.

# 30. Summary

* **Dynamic Programming (DP)** is an optimization technique that solves problems by **breaking them into overlapping subproblems**, solving each only once, and **storing the results** for reuse.
* A problem is suitable for DP only if it exhibits **Optimal Substructure** and **Overlapping Subproblems**.
* The **Principle of Optimality**, introduced by **Richard Bellman**, states that an optimal solution is composed of optimal solutions to its subproblems.
* DP can be implemented using **Memoization (Top-Down)** or **Tabulation (Bottom-Up)**.
* Compared to naive recursion, DP often reduces exponential time complexity to polynomial time.
* A structured approach—**identify state, recurrence, base cases, and implementation strategy**—is key to solving DP problems effectively.
