# Unit 7: String Matching & NP Completeness

## Topic 7.6 — Introduction to NP Completeness

## 1. Introduction

**NP Completeness** is a concept used to classify computational problems based on how difficult they are to solve.

The important classes in this syllabus are:

- **P**
- **NP**
- **NP-Complete**

The main question is:

> Can a solution to a problem be verified efficiently, even if finding that solution may be difficult?

---

# 2. Decision Problems

NP classification is mainly discussed using **decision problems**.

A decision problem has an answer of:

```text
YES / NO
```

### Example

Instead of asking:

> What is the shortest path from A to B?

we can ask:

> Is there a path from A to B having length ≤ 10?

Answer:

```text
YES
```

or

```text
NO
```

---

# 3. Class P

**P** stands for **Polynomial Time**.

A problem belongs to P if it can be **solved** by a deterministic algorithm in polynomial time.

Examples:

- Binary Search
- Sorting
- Breadth First Search
- Depth First Search
- Minimum Spanning Tree

Typical polynomial complexities include:

$$
O(n)
$$

$$
O(n\log n)
$$

$$
O(n^2)
$$

$$
O(n^3)
$$

These are considered polynomial-time complexities.

---

# 4. Class NP

**NP** stands for **Nondeterministic Polynomial Time**.

A problem belongs to NP if a proposed solution can be **verified in polynomial time**.

The important distinction is:

> **NP does not mean "not polynomial."**

It refers to problems for which a given solution can be checked efficiently.

---

# 5. Simple Example of Verification

Consider the problem:

> Does a graph contain a Hamiltonian Cycle?

Suppose someone gives us this proposed cycle:

```text
A → B → C → D → E → A
```

We can check efficiently whether:

1. Every required vertex is included.
2. No vertex is repeated incorrectly.
3. Every required edge exists.
4. The cycle returns to the starting vertex.

If these checks can be performed in polynomial time, the problem belongs to NP.

---

# 6. P vs NP

The distinction can be remembered as:

| Class | Main Idea                                  |
| ----- | ------------------------------------------ |
| P     | Solution can be found efficiently          |
| NP    | Given solution can be verified efficiently |

Conceptually:

```text
P
↓
Efficiently solve
```

while:

```text
NP
↓
Given a solution
↓
Efficiently verify it
```

Every problem in P is also in NP:

$$
\boxed{P \subseteq NP}
$$

because if a solution can be found efficiently, it can certainly be verified efficiently.

---

# 7. Example: Sorting

Suppose we have:

```text
5 2 8 1 4
```

The problem:

> Sort the numbers.

can be solved efficiently using algorithms such as Merge Sort:

$$
O(n\log n)
$$

Therefore, sorting belongs to P.

---

# 8. Example: Hamiltonian Cycle

Given a graph:

```text
A ----- B
|       |
|       |
D ----- C
```

A Hamiltonian cycle visits every vertex exactly once and returns to the starting vertex.

For example:

```text
A → B → C → D → A
```

If this cycle is given to us, we can verify it efficiently.

Therefore, the **Hamiltonian Cycle decision problem belongs to NP**.

---

# 9. NP-Complete Problems

An **NP-Complete** problem satisfies two conditions:

### Condition 1

It belongs to NP.

### Condition 2

Every problem in NP can be reduced to it in polynomial time.

Therefore:

$$
\boxed{\text{NP-Complete} = NP + NP\text{-hard}}
$$

More precisely, an NP-Complete problem is:

- in NP
- NP-hard

---

# 10. NP-Hard

A problem is **NP-hard** if it is at least as hard as every problem in NP under polynomial-time reductions.

An NP-hard problem does **not necessarily have to belong to NP**.

Therefore:

```text
NP-Complete
    =
NP
    +
NP-Hard
```

---

# 11. Relationship Between P, NP and NP-Complete

Conceptually:

```text
             NP
      ┌─────────────────┐
      │                 │
      │     P           │
      │   ┌─────┐       │
      │   │     │       │
      │   └─────┘       │
      │                 │
      │   NP-Complete   │
      │                 │
      └─────────────────┘
```

The exact relationship between **P and NP** is an unresolved fundamental question in computer science.

The important established relationship is:

$$
P \subseteq NP
$$

---

# 12. What Is Polynomial-Time Reduction?

Reduction is one of the most important concepts in NP Completeness.

Suppose we have two problems:

```text
Problem A
Problem B
```

If we can transform an instance of A into an instance of B in polynomial time:

```text
A
↓
Polynomial-time transformation
↓
B
```

then we say:

$$
\boxed{A \leq_p B}
$$

This means:

> Problem A can be reduced to Problem B in polynomial time.

---

# 13. Why Reduction Is Important

Suppose:

```text
A ≤p B
```

This tells us that if we had an efficient algorithm for B, we could use it to solve A efficiently.

Conceptually:

```text
Input for A
     ↓
Convert to B
     ↓
Solve B
     ↓
Use result for A
```

Therefore, B is at least as difficult as A under this reduction.

---

# 14. Proving a Problem Is NP-Complete

To prove that a problem `X` is NP-Complete, generally show:

### Step 1 — Show X belongs to NP

Demonstrate that a proposed solution can be verified in polynomial time.

### Step 2 — Show X is NP-hard

Take a known NP-Complete problem `Y` and reduce it to `X`:

$$
Y \leq_p X
$$

Therefore:

```text
Known NP-Complete Problem
          ↓
Polynomial Reduction
          ↓
New Problem
```

Then `X` is NP-Complete.

---

# 15. Important Direction of Reduction

Suppose we want to prove:

```text
B is NP-Complete
```

We should reduce a known NP-Complete problem **to B**:

$$
\boxed{A \leq_p B}
$$

where `A` is already known to be NP-Complete.

### Common mistake

Incorrect direction:

$$
B \leq_p A
$$

This alone does not prove that B is NP-hard.

Remember:

> **Known hard problem → New problem**

---

# 16. Example Concept

Suppose:

```text
A = Known NP-Complete problem
B = Problem we want to classify
```

If:

$$
A \leq_p B
$$

then solving B efficiently would allow us to solve A efficiently.

Therefore B is at least as hard as A.

If B is also in NP:

$$
B \in NP
$$

then:

$$
\boxed{B\text{ is NP-Complete}}
$$

---

# 17. Hamiltonian Cycle

Hamiltonian Cycle is an important problem in this syllabus.

### Definition

Given a graph, determine whether there exists a cycle that:

- visits every vertex exactly once
- returns to the starting vertex

---

# 18. Example

Consider:

```text
A ----- B
|       |
|       |
D ----- C
```

Possible Hamiltonian cycle:

```text
A → B → C → D → A
```

Every vertex appears exactly once before returning to A.

Therefore, the answer to the decision question:

> Does this graph contain a Hamiltonian cycle?

is:

```text
YES
```

---

# 19. Hamiltonian Cycle Decision Problem

Input:

```text
A graph G
```

Question:

> Does G contain a Hamiltonian cycle?

Output:

```text
YES
```

or

```text
NO
```

The Hamiltonian Cycle decision problem is an **NP-Complete problem**.

---

# 20. Hamiltonian Cycle vs Euler Cycle

These two are commonly confused.

| Hamiltonian Cycle                | Euler Cycle                           |
| -------------------------------- | ------------------------------------- |
| Visits every vertex exactly once | Uses every edge exactly once          |
| Concerned with vertices          | Concerned with edges                  |
| Hamiltonian Cycle is NP-Complete | Euler Cycle can be solved efficiently |

### Remember

```text
Hamiltonian → Vertices
Euler       → Edges
```

---

# 21. Verification of Hamiltonian Cycle

Suppose the graph has:

```text
n vertices
```

and a proposed cycle is:

```text
v1 → v2 → v3 → ... → vn → v1
```

To verify it, we can check:

### 1. Every vertex occurs

```text
v1, v2, ..., vn
```

### 2. No vertex is repeated

Except the starting vertex appearing again at the end.

### 3. Required edges exist

Check:

```text
(v1,v2)
(v2,v3)
...
(vn,v1)
```

These checks can be performed in polynomial time.

Therefore, Hamiltonian Cycle is in NP.

---

# 22. Important Terms

## Polynomial Time

Running time bounded by a polynomial in input size.

Examples:

$$
O(n)
$$

$$
O(n^2)
$$

$$
O(n^3)
$$

---

## Certificate

A proposed solution that allows us to verify whether the answer is YES.

For Hamiltonian Cycle:

```text
A → B → C → D → A
```

can act as the certificate.

---

## Verification

Checking whether the certificate is a valid solution.

---

## Reduction

Transforming one problem into another in polynomial time.

---

## NP-Hard

At least as hard as every problem in NP under polynomial-time reductions.

---

## NP-Complete

A problem that is:

```text
In NP
+
NP-Hard
```

---

# 23. Quick Comparison

| Property                                    | P               | NP                    | NP-Complete       |
| ------------------------------------------- | --------------- | --------------------- | ----------------- |
| Solution can be found in polynomial time    | Yes             | Not necessarily known | Not known         |
| Solution can be verified in polynomial time | Yes             | Yes                   | Yes               |
| NP-hard                                     | Not necessarily | Not necessarily       | Yes               |
| Example                                     | BFS             | Hamiltonian Cycle     | Hamiltonian Cycle |

For NP-Complete problems, it is important to avoid saying that **no polynomial-time algorithm exists**. The unresolved question of whether `P = NP` means this has not been established in general.


```text
NP

```

```text
NP-Complete
↓
Problem is in NP
```

### Important Relationship

$$
\boxed{P \subseteq NP}
$$

### NP-Complete Proof

```text
1. Show B ∈ NP
          ↓
2. Take known NP-Complete problem A
          ↓
3. Show A ≤p B
          ↓
4. B is NP-Hard
          ↓
5. Therefore B is NP-Complete
```

### Key Example

$$
\boxed{\text{Hamiltonian Cycle is NP-Complete}}
$$

> **Core idea:** NP Completeness helps us understand problems for which solutions may be difficult to find but can be efficiently verified, and polynomial-time reductions allow us to compare the computational difficulty of problems.
