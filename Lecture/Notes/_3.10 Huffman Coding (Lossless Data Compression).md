# 3. Why Compression?

Suppose a text file contains:

```
AAAAAAAAAABBBBBCCCD
```

Instead of storing every character using the same number of bits,

we assign:

* Short codes to frequent characters.
* Long codes to rare characters.

This reduces the total file size.

# 4. Types of Compression

## A. Lossless Compression

Original data can be recovered **exactly**.

Examples:

* ZIP files
* PNG images
* PDF documents (many internal streams)
* Source code files

---

## B. Lossy Compression

Some information is permanently discarded.

Examples:

* JPEG images
* MP3 audio
* MPEG video

---

### Comparison

| Lossless                        | Lossy                         |
| ------------------------------- | ----------------------------- |
| Original data recovered exactly | Some information is lost      |
| No quality loss                 | Quality may decrease          |
| Used for text and programs      | Used for images, audio, video |
| Example: ZIP                    | Example: JPEG                 |

# 5. Fixed-Length Encoding

Suppose we have four characters.

| Character | Binary Code |
| --------- | ----------- |
| A         | 00          |
| B         | 01          |
| C         | 10          |
| D         | 11          |

Every character uses:

```

```

Even if one character appears much more frequently than others.

This is inefficient.

# 6. Variable-Length Encoding

Instead of assigning equal-length codes,

assign:

| Character | Frequency | Code |
| --------- | --------: | ---- |
| A         |        50 | 0    |
| B         |        25 | 10   |
| C         |        15 | 110  |
| D         |        10 | 111  |

Frequently occurring characters get **shorter codes**.

Rare characters get **longer codes**.

Average number of bits decreases.

---

# 7. Prefix Code

## Definition

A **Prefix Code** is a code in which **no codeword is the prefix of another codeword**.

Example:

Correct:

| Character | Code |
| --------- | ---- |
| A         | 0    |
| B         | 10   |
| C         | 110  |
| D         | 111  |

Notice:

* `0` is not the prefix of `10`
* `10` is not the prefix of `110`
* `110` is not the prefix of `111`

Therefore,

decoding is unambiguous.

---

Incorrect Example

| Character | Code |
| --------- | ---- |
| A         | 0    |
| B         | 01   |
| C         | 011  |

Here,

```
0
```

is a prefix of

```
01
```

This creates ambiguity during decoding.

---

# 8. What is Huffman Coding?

Huffman Coding is a **Greedy Algorithm** used to generate an **optimal prefix code** based on character frequencies.

Idea:

* Higher frequency → shorter code
* Lower frequency → longer code

This minimizes the total number of bits required.

---

# 9. Greedy Strategy

At each step,

choose the **two nodes with the smallest frequencies**.

Merge them into a new node.

Repeat until only one node remains.

This is the Greedy Choice.

# 14. Why Huffman is Greedy

At every step,

it chooses the **two smallest frequencies**.

This local optimal choice leads to the globally optimal prefix code.

Hence,

Huffman Coding satisfies:

* Greedy Choice Property
* Optimal Substructure

---

# 15. Algorithm

1. Create a leaf node for every character.
2. Insert all nodes into a Min Heap.
3. Remove the two nodes with minimum frequency.
4. Merge them into a new internal node.
5. Insert the new node back into the Min Heap.
6. Repeat until one node remains.
7. Traverse the tree to generate codes.

---

# 16. Pseudocode

```text
Insert all characters into Min Heap

while(heap size > 1)

     x = remove minimum

     y = remove minimum

     z = merge(x,y)

     insert(z)

Traverse tree

Generate binary codes
```

# 17. Java Implementation

```java
import java.util.*;

class Node {
    char ch;
    int freq;
    Node left, right;

    Node(char ch, int freq) {
        this.ch = ch;
        this.freq = freq;
    }

    Node(int freq, Node left, Node right) {
        this.ch = '\0';
        this.freq = freq;
        this.left = left;
        this.right = right;
    }
}

public class HuffmanCoding {

    static void printCodes(Node root, String code) {

        if(root == null)
            return;

        if(root.left == null && root.right == null){

            System.out.println(root.ch + " : " + code);
        }

        printCodes(root.left, code + "0");

        printCodes(root.right, code + "1");
    }

    public static void main(String[] args){

        char[] chars = {'A','B','C','D','E','F'};
        int[] freq = {5,9,12,13,16,45};

        PriorityQueue<Node> pq =
            new PriorityQueue<>(Comparator.comparingInt(a -> a.freq));

        for(int i=0;i<chars.length;i++)
            pq.offer(new Node(chars[i],freq[i]));

        while(pq.size()>1){

            Node left = pq.poll();
            Node right = pq.poll();

            Node merged =
                new Node(left.freq + right.freq, left, right);

            pq.offer(merged);
        }

        printCodes(pq.poll(),"");
    }
}
```

# 18. C++ Implementation

```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

struct Node {
    char ch;
    int freq;
    Node *left, *right;

    Node(char c, int f) {
        ch = c;
        freq = f;
        left = right = nullptr;
    }

    Node(int f, Node *l, Node *r) {
        ch = '\0';
        freq = f;
        left = l;
        right = r;
    }
};

struct Compare {
    bool operator()(Node *a, Node *b) {
        return a->freq > b->freq;
    }
};

void printCodes(Node *root, string code) {

    if(root == nullptr)
        return;

    if(root->left == nullptr && root->right == nullptr)
        cout << root->ch << " : " << code << endl;

    printCodes(root->left, code + "0");
    printCodes(root->right, code + "1");
}

int main() {

    priority_queue<Node*, vector<Node*>, Compare> pq;

    char chars[] = {'A','B','C','D','E','F'};
    int freq[] = {5,9,12,13,16,45};

    for(int i=0;i<6;i++)
        pq.push(new Node(chars[i], freq[i]));

    while(pq.size() > 1){

        Node *left = pq.top(); pq.pop();
        Node *right = pq.top(); pq.pop();

        Node *merged =
            new Node(left->freq + right->freq, left, right);

        pq.push(merged);
    }

    printCodes(pq.top(), "");

    return 0;
}
```

# 19. Time Complexity

| Operation          | Complexity |
| ------------------ | ---------: |
| Insert all nodes   | O(n log n) |
| Build Huffman Tree | O(n log n) |
| Generate codes     |       O(n) |

Overall:

```text
O(n log n)
```

where **n** is the number of distinct characters.

# 21. Advantages

* Produces an optimal prefix code.
* Completely lossless.
* Reduces storage and transmission costs.
* Efficient using a priority queue.
* Widely used in practical compression systems.

---

# 22. Limitations

* Requires knowledge of character frequencies before encoding.
* Less effective if all characters occur with nearly equal frequencies.
* Additional space is needed to store or reconstruct the Huffman tree (or an equivalent code table).

---

# 23. Common Mistakes

* Selecting the largest frequencies instead of the smallest.
* Forgetting that Huffman codes must satisfy the prefix property.
* Confusing Huffman trees with Binary Search Trees.
* Assuming Huffman Coding performs lossy compression.
* Not restarting traversal from the root after decoding a character.

---

# 24. Best Practices

* Always use a **Priority Queue (Min Heap)** for efficiency.
* Clearly label left edges as `0` and right edges as `1` (or vice versa, but be consistent).
* Verify that generated codes satisfy the prefix property.
* Practice constructing Huffman trees manually before writing code.

# 30. Summary

* **Huffman Coding** is a **Greedy Algorithm** used to generate an **optimal prefix code** for **lossless data compression**.
* It assigns **shorter binary codes to frequently occurring characters** and **longer codes to less frequent characters**, minimizing the average number of bits per character.
* The algorithm repeatedly merges the **two nodes with the smallest frequencies** using a **Priority Queue (Min Heap)** to build a **Huffman Tree**.
* Huffman Coding satisfies both the **Greedy Choice Property** and **Optimal Substructure**, ensuring an optimal encoding.
* The overall time complexity is **O(n log n)**, making it efficient for practical compression systems.
* Huffman Coding is widely used as a building block in file compression and data transmission technologies.
