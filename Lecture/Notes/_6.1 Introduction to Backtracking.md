# Unit 6: Backtracking and Branch & Bound

## Topic 6.1 — Introduction to Backtracking

## 1. Introduction

**Backtracking** is an algorithmic technique used to solve problems by building a solution **step by step**.

If the current partial solution cannot lead to a valid solution, the algorithm:

1. **Backtracks** to the previous decision.
2. Makes another choice.
3. Continues searching.

### Basic idea

```text
Choose
  ↓
Explore
  ↓
Valid?
 ├── Yes → Continue
 └── No  → Backtrack
```

Backtracking is essentially a **systematic trial-and-error technique with pruning**.

---

# 2. Simple Example

Suppose we need to find a path through a maze.

```text
Start
  ↓
Choose a path
  ↓
Is it valid?
  ├── Yes → Continue
  └── No  → Go back
```

If a selected path reaches a dead end:

```text
Start → A → B → Dead End
             ↑
             Backtrack
```

The algorithm returns to `A` and tries another path.

---

# 3. Why Backtracking Is Needed

Some problems have a large number of possible solutions.

For example, if we have several choices:

```text
Choice 1
 ├── Choice 1
 │    ├── ...
 │    └── ...
 └── Choice 2
      ├── ...
      └── ...
```

Trying every possibility blindly can be expensive.

Backtracking avoids continuing along a path as soon as it determines that the partial solution is invalid.

This is called **pruning**.

---

# 4. Backtracking and State-Space Tree

Backtracking problems can be represented using a **state-space tree**.

Each node represents a **partial solution**.

Consider choosing two binary values:

```text
             Start
            /     \
          0         1
         / \       / \
        00  01    10  11
```

Each path from the root represents a sequence of decisions.

For example:

```text
Start → 0 → 1
```

represents:

```text
01
```

---

# 5. General Structure of Backtracking

A backtracking algorithm generally follows:

```text
1. Make a choice.
2. Check whether the choice is promising.
3. If promising:
      Continue recursively.
4. If not promising:
      Reject the choice.
5. Undo the choice.
6. Try the next choice.
```

The **undo** step is the key feature of backtracking.

---

# 6. General Backtracking Template

```text
Backtrack(state)

    if solution is complete:
        process solution
        return

    for each possible choice:

        if choice is promising:

            make choice

            Backtrack(new state)

            undo choice
```

The term **promising** means that the current partial solution still has the possibility of becoming a valid solution.

public class BinaryStrings {

    static void generate(String current, int n) {

        // Solution completed
        if (current.length() == n) {

        generate(current + "0", n);

        // Choose 1
        generate(current + "1", n);

# 11. Example with Actual Backtracking

The previous example creates choices recursively, but it does not explicitly modify and undo a shared structure.

A clearer example is generating permutations.

Consider:

```text
{1, 2, 3}
```

We want all permutations.

The first choice can be:

```text
1
2
3
```

Suppose we choose `1`.

```text
1
├── 2
│   └── 3 → 123
└── 3
    └── 2 → 132
```

After completing `123`, we **undo the choice** and try `3`.

This is backtracking.

---

# 12. Backtracking Steps for Permutations

For `{1,2,3}`:

```text
Choose 1
    Choose 2
        Choose 3
            123
        Backtrack
    Choose 3
        Choose 2
            132
        Backtrack

Choose 2
    ...
```

The complete result is:

```text
123
132
213
231
312
321
```

# 13. Important Components of Backtracking

| Component  | Meaning                                             |
| ---------- | --------------------------------------------------- |
| State      | Current partial solution                            |
| Choice     | Decision being considered                           |
| Constraint | Condition that must be satisfied                    |
| Promising  | Partial solution can still lead to a valid solution |
| Backtrack  | Undo the previous choice                            |
| Pruning    | Stop exploring an invalid branch                    |

---

# 14. Backtracking vs Brute Force

### Brute Force

Brute force generally examines all possible solutions.

```text
Generate all possibilities
        ↓
Check every possibility
```

### Backtracking

Backtracking stops exploring a branch as soon as it becomes invalid.

```text
Generate choice
      ↓
Check constraint
      ↓
Invalid?
 └── Yes → Prune
```

Therefore, backtracking can avoid exploring many unnecessary possibilities.

However, backtracking problems can still have **exponential or factorial worst-case complexity**.

Backtracking is commonly used for:

- **N-Queens Problem**
- **0/1 Knapsack** in a backtracking approach
- **Travelling Salesman Problem**
- Generating permutations

- Constraint-satisfaction problems

# 16. Backtracking and Recursion

Backtracking is commonly implemented using recursion.

The recursive function represents the current state.

For example:

```text
Backtrack()
    |
    +-- Choice 1
    |     |
    |     +-- Backtrack()
    |
    +-- Choice 2
          |
          +-- Backtrack()
```

The recursive call moves forward, while returning from the recursive call performs the backtracking.

---

# 17. Backtracking Example — N-Queens

The **N-Queens problem** asks us to place `N` queens on an `N × N` chessboard such that no two queens attack each other.

For `4` queens:

```text
. Q . .
. . . Q
Q . . .
. . Q .
```

No two queens share:

- The same row
- The same column
- The same diagonal

Backtracking places queens one row at a time.

```text
Place Queen
    ↓
Check Safe?
 ├── Yes → Place next queen
 └── No  → Try another column
```

If no column is possible:

```text
Backtrack
```

The detailed N-Queens algorithm will be covered in its dedicated topic.

# 18. Pruning

**Pruning** means eliminating a branch that cannot produce a valid solution.

Example:

```text
             Start
            /     \
         Valid    Invalid
                   X
```

The invalid branch is not explored further.

Without pruning:

```text
Explore everything
```

With pruning:

```text
Explore only promising branches
```

This is the major advantage of backtracking over simple exhaustive search.

---

# 19. Time Complexity

There is no single time complexity for all backtracking problems.

It depends on:

- Number of possible choices
- Depth of the solution tree
- Constraints
- Amount of pruning

Many backtracking problems have exponential or factorial worst-case complexity.

Examples:

```text
Binary choices of depth n → O(2ⁿ)
Permutations of n items    → O(n!)
```

Effective pruning can significantly reduce the number of states actually explored, but it does not necessarily change the worst-case complexity.

---

# 20. Backtracking vs Dynamic Programming

These techniques solve problems differently.

| Feature          | Backtracking              | Dynamic Programming                |
| ---------------- | ------------------------- | ---------------------------------- |
| Main idea        | Search possible solutions | Store and reuse subproblem results |
| Typical approach | Recursive search          | Recursion + memoization / table    |
| Focus            | Constraints and choices   | Overlapping subproblems            |
| Pruning          | Important                 | Usually not the main technique     |
| Examples         | N-Queens, TSP             | LCS, Matrix Chain Multiplication   |

# 21. Common Mistakes

### 1. Forgetting to undo a choice

After recursive exploration:

```text
make choice
↓
recursive call
↓
undo choice
```

The undo step is essential when modifying a shared solution.

### 2. Not checking constraints

A branch should be rejected as soon as it violates a constraint.

### 3. Missing the base case

The algorithm must know when a complete solution has been reached.

### 4. Confusing backtracking with ordinary recursion

Recursion is a programming technique.

Backtracking is a **problem-solving strategy** that uses systematic choices, constraint checking, and undoing decisions.

### Key Points

- **Backtracking** builds a solution incrementally.
- It explores possible choices systematically.
- Invalid or non-promising branches are **pruned**.
- It commonly uses **recursion**.
- A **state-space tree** represents possible choices.
- The general pattern is:
  **Choose → Check → Explore → Undo → Try next choice**.
- Important syllabus applications are:

  - 0/1 Knapsack
  - N-Queens
  - Travelling Salesman Problem.
