## 2. Basic Graph Terminology

Consider a graph:

```text
       A
      / \
     B---C
     |
     D
```

Here:

* Vertices = `{A, B, C, D}`
* Edges = `{(A,B), (A,C), (B,C), (B,D)}`

### Important Terms

| Term              | Meaning                                           |
| ----------------- | ------------------------------------------------- |
| Vertex            | A node in a graph                                 |
| Edge              | Connection between two vertices                   |
| Adjacent vertices | Vertices directly connected by an edge            |
| Degree            | Number of edges connected to a vertex             |
| Path              | Sequence of vertices connected by edges           |
| Cycle             | Path that starts and ends at the same vertex      |
| Connected graph   | Every vertex is reachable from every other vertex |
| Weight            | Numerical value assigned to an edge               |

For example, in the above graph:

```text
Degree(A) = 2
Degree(B) = 3
Degree(C) = 2
Degree(D) = 1
```

# 3. Graphs and Games

Graphs are also useful for representing **games and possible moves**.

A game can be represented as a graph where:

* **Vertex** → A possible state of the game
* **Edge** → A legal move from one state to another

For example, suppose a game has three states:

```text
        Move 1
   S0 ----------> S1
    |
    | Move 2
    v
   S2
```

Here:

* `S0` is the current game state.
* A player can make either Move 1 or Move 2.
* Each move changes the game state.

This representation is called a **state-space graph**.

### Example: Tic-Tac-Toe

A Tic-Tac-Toe game can be represented using a graph:

```text
Initial Board
      |
  Player X moves
      |
   State 1
    /   \
   /     \
State 2  State 3
  |        |
 ...      ...
  |
Terminal State
```

Each node represents a board configuration, and each edge represents a valid move.

The graph can therefore be used to analyze possible moves and outcomes.

# 4. Types of Graphs

The syllabus primarily requires understanding graphs before graph traversal. Two important types are:

## 4.1 Undirected Graph

In an **undirected graph**, edges do not have a direction.

```text
A ----- B
|       |
|       |
C ----- D
```

The edge:

```text
A ----- B
```

means:

```text
A is connected to B
B is connected to A
```

Therefore, `(A,B)` and `(B,A)` represent the same edge.

### Example

Roads connecting two cities without a specified direction can be represented using an undirected graph.

---

## 4.2 Directed Graph

In a **directed graph**, every edge has a direction.

```text
A -----> B
|        |
v        v
C -----> D
```

The edge:

```text
A -----> B
```

means:

```text
A → B
```

but it does not necessarily mean:

```text
B → A
```

Directed graphs are also called **digraphs**.

### Example

A one-way road system can be represented using a directed graph.

---

# 5. Weighted Graph

A graph can also contain weights on its edges.

```text
      5
 A -------- B
 |          |
2|          |3
 |          |
 C -------- D
      4
```

The numbers represent the cost, distance, or time associated with each edge.

For example:

```text
A → B = 5
A → C = 2
B → D = 3
C → D = 4
```

Weighted graphs are important for algorithms such as:

* Dijkstra's algorithm
* Minimum Spanning Tree
* Floyd-Warshall algorithm

# 6. Graph Representation

A graph can be represented mainly using:

1. **Adjacency Matrix**
2. **Adjacency List**

These representations are important because the graph traversal algorithms in this unit will use them.

---

## 6.1 Adjacency Matrix

An adjacency matrix uses a two-dimensional array.

Consider:

```text
A ----- B
|
|
C
```

The adjacency matrix is:

|   |  A |  B |  C |
| - | -: | -: | -: |
| A |  0 |  1 |  1 |
| B |  1 |  0 |  0 |
| C |  1 |  0 |  0 |

`1` means an edge exists.

`0` means an edge does not exist.

### Matrix Representation

```text
    A B C
A [ 0 1 1 ]
B [ 1 0 0 ]
C [ 1 0 0 ]
```

### Advantages

* Simple to implement.
* Checking whether an edge exists takes **O(1)** time.
* Suitable for dense graphs.

### Disadvantage

Requires:

```text
O(V²)
```

space even when the graph has very few edges.

---

# 7. Adjacency List

An adjacency list stores the neighboring vertices of each vertex.

For:

```text
A ----- B
|
|
C
```

the adjacency list is:

```text
A → B, C
B → A
C → A
```

### Example

```text
A: B C
B: A
C: A
```

For an undirected graph, an edge is stored in both lists.

For example:

```text
A ----- B
```

is stored as:

```text
A → B
B → A
```

### Advantages

* Requires less memory for sparse graphs.
* Easy to traverse neighboring vertices.
* Commonly used with DFS and BFS.

### Space Complexity

```text
O(V + E)
```

where:

* `V` = number of vertices
* `E` = number of edges

---

# 8. Adjacency Matrix vs Adjacency List

| Feature        | Adjacency Matrix      | Adjacency List      |
| -------------- | --------------------- | ------------------- |
| Representation | 2D array              | List of neighbors   |
| Space          | O(V²)                 | O(V + E)            |
| Check edge     | O(1)                  | O(degree of vertex) |
| Suitable for   | Dense graphs          | Sparse graphs       |
| Traversal      | Can be less efficient | Efficient           |
| Common use     | Small/dense graphs    | DFS, BFS            |

# 10. Graph Implementation in Java

Using an adjacency list:

```java
import java.util.*;

public class Graph {
    private int vertices;
    private ArrayList<ArrayList<Integer>> adj;

    Graph(int vertices) {
        this.vertices = vertices;
        adj = new ArrayList<>();

        for (int i = 0; i < vertices; i++) {
            adj.add(new ArrayList<>());
        }
    }

    void addEdge(int u, int v) {
        adj.get(u).add(v);
        adj.get(v).add(u); // Undirected graph
    }

    void display() {
        for (int i = 0; i < vertices; i++) {
            System.out.print(i + " -> ");

            for (int vertex : adj.get(i)) {
                System.out.print(vertex + " ");
            }

            System.out.println();
        }
    }

    public static void main(String[] args) {
        Graph graph = new Graph(4);

        graph.addEdge(0, 1);
        graph.addEdge(0, 2);
        graph.addEdge(1, 2);
        graph.addEdge(1, 3);

        graph.display();
    }
}
```

### Output

```text
0 -> 1 2
1 -> 0 2 3
2 -> 0 1
3 -> 1
```

# 11. Graph Implementation in C++

```cpp
#include <iostream>
#include <vector>
using namespace std;

class Graph {
private:
    int vertices;
    vector<vector<int>> adj;

public:
    Graph(int vertices) {
        this->vertices = vertices;
        adj.resize(vertices);
    }

    void addEdge(int u, int v) {
        adj[u].push_back(v);
        adj[v].push_back(u); // Undirected graph
    }

    void display() {
        for (int i = 0; i < vertices; i++) {
            cout << i << " -> ";

            for (int vertex : adj[i]) {
                cout << vertex << " ";
            }

            cout << endl;
        }
    }
};

int main() {
    Graph graph(4);

    graph.addEdge(0, 1);
    graph.addEdge(0, 2);
    graph.addEdge(1, 2);
    graph.addEdge(1, 3);

    graph.display();

    return 0;
}
```

# 12. Graphs in Algorithm Design

Graphs are used to solve many real-world problems.

| Problem              | Graph Representation                               |
| -------------------- | -------------------------------------------------- |
| Road networks        | Cities = vertices, roads = edges                   |
| Social networks      | People = vertices, relationships = edges           |
| Computer networks    | Computers = vertices, connections = edges          |
| Web pages            | Pages = vertices, hyperlinks = directed edges      |
| Game states          | Game states = vertices, moves = edges              |
| Course prerequisites | Courses = vertices, prerequisites = directed edges |

Graph algorithms can then be applied to these representations.

For example:

```text
Graph
  |
  +-- Traversal
  |     |
  |     +-- DFS
  |     +-- BFS
  |
  +-- Shortest Path
  |
  +-- Minimum Spanning Tree
  |
  +-- Topological Sorting
```

This forms the foundation for the remaining topics in graph algorithms.

# 13. Best Practices

1. Clearly identify whether the graph is **directed or undirected**.
2. Identify whether edges have **weights**.
3. Use an **adjacency matrix** when the graph is small or dense.
4. Use an **adjacency list** for large sparse graphs.
5. For undirected graphs, add both:

   ```text
   u → v
   v → u
   ```
6. For directed graphs, add only:

   ```text
   u → v
   ```
7. Keep track of visited vertices during graph traversal to avoid repeated processing.

# 14. Common Mistakes

### Mistake 1: Treating a directed edge as undirected

```text
A → B
```

does not automatically mean:

```text
B → A
```

### Mistake 2: Adding only one direction in an undirected graph

For:

```text
A ----- B
```

both must be stored:

```text
A → B
B → A
```

### Mistake 3: Confusing path and edge

An **edge** directly connects two vertices.

A **path** can contain multiple edges.

Example:

```text
A → B → C → D
```

is a path containing three edges.

# 16. Quick Revision

* A **graph** consists of vertices and edges.
* A **vertex** represents an object or state.
* An **edge** represents a relationship or transition.
* **Undirected graph:** edges have no direction.
* **Directed graph:** edges have direction.
* **Weighted graph:** edges contain values such as cost or distance.
* **Adjacency matrix:** requires `O(V²)` space.
* **Adjacency list:** requires `O(V + E)` space.
* Graphs can represent **game states and possible moves**.
* Graph representation is the foundation for **DFS, BFS and Topological Sort**.
