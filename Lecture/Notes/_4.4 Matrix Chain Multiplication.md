2. Real-World Motivation

Suppose we have three matrices:

A × B × C

We know matrix multiplication is associative:

(A × B) × C = A × (B × C)

Therefore, both produce the same final matrix.

But there is an important difference:

The number of scalar multiplications can be different.

So the problem is:

How should we place parentheses so that the total number of scalar multiplications is minimum?

This is the Matrix Chain Multiplication Problem.

⸻

3. Important Clarification

MCM does not actually multiply the matrices.

It only determines:

The most efficient order in which the matrices should be multiplied.

This is a very important point for exams.

⸻

Suppose:

A = p × q
B = q × r

Then:

A × B

Cost of Multiplication

The number of scalar multiplications is:

B = 20 × 30

The final matrix is the same.

Cost 1 = 18000
Cost 2 = 32000

Matrix multiplication is associative, but different parenthesizations can have different computational costs.

7. Why Dynamic Programming?

Suppose we have:

A × B × C × D × E

The number of possible parenthesizations increases rapidly as the number of matrices increases.

The number of ways to fully parenthesize n matrices is:

Catalan(n-1)

For example:

Matrices	Parenthesizations
2	1
3	2
4	5
5	14
6	42
7	132

Trying every possibility becomes expensive.

Dynamic Programming avoids repeated calculations.

⸻

8. Problem Statement

Given a sequence of matrices:

A1, A2, A3, ..., An

Determine the parenthesization that minimizes the number of scalar multiplications.

⸻

9. Representation Using Dimensions

Suppose:

A1 = 10 × 20
A2 = 20 × 30
A3 = 30 × 40

We represent dimensions using:

p = [10, 20, 30, 40]

Because:

A1 = p[0] × p[1]
A2 = p[1] × p[2]
A3 = p[2] × p[3]

This representation is very important in implementation.

10. DP State

Define:

dp[i][j]

as:

The minimum number of scalar multiplications required to multiply matrices Ai through Aj.

For example:

dp[2][4]

means:

Minimum cost of multiplying A2 × A3 × A4.

⸻

11. Base Case

If there is only one matrix:

Ai

there is no multiplication.

Therefore:

dp[i][i] = 0

⸻

12. Main Idea

Suppose we want to calculate:

A1 × A2 × A3 × A4

There are different positions where we can split the chain.

For example:

(A1) × (A2 A3 A4)

or

(A1 A2) × (A3 A4)

or

(A1 A2 A3) × (A4)

For every possible split, calculate the total cost and select the minimum.

⸻

13. Understanding the Split

Suppose we split between:

Ak

and

Ak+1

Then:

Ai ... Aj

becomes:

(Ai ... Ak) × (Ak+1 ... Aj)

There are three costs:

Cost 1

Multiply the left chain:

dp[i][k]

Cost 2

Multiply the right chain:

dp[k+1][j]

Cost 3

Multiply the two resulting matrices:

p[i-1] × p[k] × p[j]

Therefore:

Total Cost =
dp[i][k]
+
dp[k+1][j]
+
p[i-1] × p[k] × p[j]

⸻

14. MCM Recurrence

Therefore:

dp[i][j] =
min {
    dp[i][k]
    +
    dp[k+1][j]
    +
    p[i-1] × p[k] × p[j]
}

where:

i ≤ k < j

This is the most important formula in Matrix Chain Multiplication.

⸻

18. Optimal Parenthesization

We can also determine the multiplication order.

For:

dp[1][4]

the best split was:

k = 3

Therefore:

(A1 A2 A3) × A4

For:

dp[1][3]

the best split was:

k = 2

Therefore:

(A1 A2) × A3

So the optimal parenthesization is:

((A1 × A2) × A3) × A4

19. Algorithm — Tabulation

MATRIX_CHAIN(p):
    n = number of matrices
    for i = 1 to n:
        dp[i][i] = 0
    for length = 2 to n:
        for i = 1 to n-length+1:
            j = i + length - 1
            dp[i][j] = infinity
            for k = i to j-1:
                cost =
                    dp[i][k]
                    +
                    dp[k+1][j]
                    +
                    p[i-1] * p[k] * p[j]
                dp[i][j] =
                    min(dp[i][j], cost)
    return dp[1][n]

⸻

20. Java Implementation

public class MatrixChainMultiplication {
    static int matrixChain(int[] p) {
        int n = p.length - 1;
        int[][] dp = new int[n + 1][n + 1];
        for (int length = 2; length <= n; length++) {
            for (int i = 1;
                 i <= n - length + 1;
                 i++) {
                int j = i + length - 1;
                dp[i][j] = Integer.MAX_VALUE;
                for (int k = i; k < j; k++) {
                    long cost =
                        (long) dp[i][k]
                        + dp[k + 1][j]
                        + (long) p[i - 1]
                        * p[k]
                        * p[j];
                    if (cost < dp[i][j]) {
                        dp[i][j] = (int) cost;
                    }
                }
            }
        }
        return dp[1][n];
    }
    public static void main(String[] args) {
        int[] p = {10, 20, 30, 40, 30};
        System.out.println(
            matrixChain(p)
        );
    }
}

Output:

30000

Important implementation note

The multiplication cost can become larger than the range of a Java int for large matrix dimensions. The code therefore calculates the intermediate cost using long.

For production-quality code with potentially very large dimensions, you should also consider whether the final answer itself can exceed int.

21. C++ Implementation

#include <iostream>
#include <vector>
#include <climits>
#include <algorithm>
using namespace std;
long long matrixChain(vector<int>& p) {
    int n = p.size() - 1;
    vector<vector<long long>> dp(
        n + 1,
        vector<long long>(n + 1, 0)
    );
    for (int length = 2; length <= n; length++) {
        for (int i = 1;
             i <= n - length + 1;
             i++) {
            int j = i + length - 1;
            dp[i][j] = LLONG_MAX;
            for (int k = i; k < j; k++) {
                long long cost =
                    dp[i][k]
                    + dp[k + 1][j]
                    + 1LL * p[i - 1]
                    * p[k]
                    * p[j];
                dp[i][j] =
                    min(dp[i][j], cost);
            }
        }
    }
    return dp[1][n];
}
int main() {
    vector<int> p = {
        10, 20, 30, 40, 30
    };
    cout << matrixChain(p);
    return 0;
}

Output:

30000

22. Memoization — Top Down

We can also solve MCM recursively.

The state is:

solve(i, j)

meaning:

Minimum cost to multiply matrices i through j.

Base case

i == j

Therefore:

return 0

⸻

23. Java Memoization

import java.util.Arrays;
public class MCMMemo {
    static long[][] dp;
    static long solve(int[] p, int i, int j) {
        if (i == j)
            return 0;
        if (dp[i][j] != -1)
            return dp[i][j];
        long best = Long.MAX_VALUE;
        for (int k = i; k < j; k++) {
            long cost =
                solve(p, i, k)
                + solve(p, k + 1, j)
                + (long) p[i - 1]
                * p[k]
                * p[j];
            best = Math.min(best, cost);
        }
        return dp[i][j] = best;
    }
    public static void main(String[] args) {
        int[] p = {10, 20, 30, 40, 30};
        int n = p.length - 1;
        dp = new long[n + 1][n + 1];
        for (long[] row : dp)
            Arrays.fill(row, -1);
        System.out.println(
            solve(p, 1, n)
        );
    }
}

24. C++ Memoization

#include <iostream>
#include <vector>
#include <climits>
#include <algorithm>
using namespace std;
long long solve(
    vector<int>& p,
    int i,
    int j,
    vector<vector<long long>>& dp
) {
    if (i == j)
        return 0;
    if (dp[i][j] != -1)
        return dp[i][j];
    long long best = LLONG_MAX;
    for (int k = i; k < j; k++) {
        long long cost =
            solve(p, i, k, dp)
            + solve(p, k + 1, j, dp)
            + 1LL * p[i - 1]
            * p[k]
            * p[j];
        best = min(best, cost);
    }
    return dp[i][j] = best;
}
int main() {
    vector<int> p = {
        10, 20, 30, 40, 30
    };
    int n = p.size() - 1;
    vector<vector<long long>> dp(
        n + 1,
        vector<long long>(n + 1, -1)
    );
    cout << solve(p, 1, n, dp);
    return 0;
}

25. Complexity Analysis

There are approximately:

O(n²)

DP states.

For each state, we may try:

O(n)

possible split positions.

Therefore:

Time Complexity

O(n³)

Space Complexity

O(n²)

for the DP table.

⸻

26. Why Not Greedy?

A natural question is:

Can we simply choose the cheapest multiplication at every step?

No.

The cost of an early multiplication changes the dimensions of the resulting matrix, which affects all subsequent multiplication costs.

Therefore:

A locally optimal multiplication may lead to a globally expensive parenthesization.

MCM requires considering all possible split positions through DP.

27. MCM vs Ordinary Matrix Multiplication

Ordinary Matrix Multiplication	Matrix Chain Multiplication
Actually multiplies matrices	Finds optimal multiplication order
Produces matrix values	Produces minimum multiplication cost
Uses matrix elements	Uses dimensions
Computational operation	Optimization problem
No parenthesization search required	Parenthesization is the main problem

28. Important Exam Point

Question:

Why is Matrix Chain Multiplication a Dynamic Programming problem?

Answer:

Matrix Chain Multiplication has:

1. Optimal Substructure

The optimal solution for a matrix chain contains optimal solutions to its subchains.

2. Overlapping Subproblems

The same subchains are evaluated repeatedly when considering different parenthesizations.

Therefore, Dynamic Programming can store the results of subproblems and avoid repeated computation.

MCM does not calculate matrix values.

It calculates the minimum scalar multiplication cost and optimal order.

30. Best Practices for Solving MCM

Use this five-step method:

Step 1 — Identify matrices

A1, A2, ..., An

Step 2 — Write dimensions

p[0], p[1], ..., p[n]

Step 3 — Define state

dp[i][j]

Step 4 — Try every split

k = i ... j-1

Step 5 — Select minimum

min(all possible costs)

This framework should be memorized.

Why is MCM O(n³)?

There are O(n²) subproblems dp[i][j], and for each subproblem we try up to O(n) split positions.

Therefore:

O(n²) × O(n)
=
O(n³)

38. Exam-Oriented Answer

Define Matrix Chain Multiplication.

Matrix Chain Multiplication is a Dynamic Programming optimization problem in which the order of multiplying a sequence of matrices is determined so that the total number of scalar multiplications is minimized. Since matrix multiplication is associative, different parenthesizations produce the same final matrix but may require different computational costs.

40. Summary

* Matrix Chain Multiplication finds the most efficient order for multiplying a sequence of matrices.
* Matrix multiplication is associative, but different parenthesizations can have very different costs.
* MCM does not perform actual matrix multiplication.
* The DP state is:

dp[i][j]

representing the minimum cost of multiplying matrices Ai through Aj.

* Every possible split k is considered.
* The recurrence combines the cost of the two subchains with the cost of multiplying their resulting matrices.
* Standard Dynamic Programming takes O(n³) time and O(n²) space.
* A separate split table can be maintained to reconstruct the optimal parenthesization.
