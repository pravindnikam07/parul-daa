# Unit 7: String Matching & NP Completeness

## Topic 7.5 — String Matching Using Finite Automata

## 1. Introduction

**Finite Automata String Matching** uses a **finite automaton** to find a pattern in a text.

The basic idea is:

> Convert the pattern into a finite-state machine and process the text character by character.

The automaton keeps track of **how much of the pattern has currently been matched**.

When the complete pattern is matched, an occurrence is found.

---

# 2. Basic Idea

Suppose:

```text
Pattern = "ABC"
```

We create states:

```text
q0 → q1 → q2 → q3
```

where:

```text
q0 = No characters matched
q1 = A matched
q2 = AB matched
q3 = ABC matched
```

State `q3` represents a complete match.

```text
        A        B        C
q0 ─────────> q1 ──────> q2 ──────> q3
                                      ↑
                                  Pattern found
```

---

# 3. What Is a State?

A state represents the number of pattern characters that have been matched so far.

For:

```text
Pattern = "ABC"
```

| State | Meaning              |
| ----- | -------------------- |
| `q0`  | 0 characters matched |
| `q1`  | `A` matched          |
| `q2`  | `AB` matched         |
| `q3`  | `ABC` matched        |

Therefore:

$$
q_m
$$

represents a complete match for a pattern of length `m`.

---

# 4. Finite Automaton

A finite automaton consists of:

1. **States**
2. **Input alphabet**
3. **Transition function**
4. **Initial state**
5. **Final/accepting state**

For string matching:

```text
Initial state = 0
Final state = m
```

where `m` is the pattern length.

---

# 5. Example

Consider:

```text
Pattern = "ABAB"
```

States:

```text
q0
q1
q2
q3
q4
```

Meaning:

```text
q0 → Nothing matched
q1 → A matched
q2 → AB matched
q3 → ABA matched
q4 → ABAB matched
```

Transition for the correct sequence:

```text
q0 --A--> q1
q1 --B--> q2
q2 --A--> q3
q3 --B--> q4
```

When the automaton reaches:

```text
q4
```

the pattern has been found.

---

# 6. Why Do We Need Other Transitions?

Suppose the pattern is:

```text
ABAB
```

and the current state is:

```text
q3
```

meaning:

```text
ABA
```

If the next character is:

```text
B
```

we reach:

```text
q4
```

and find the pattern.

But suppose the next character is:

```text
A
```

The automaton should not simply return to `q0`.

It checks whether the current characters can still represent the beginning of the pattern.

This is the important part of the finite automaton approach.

---

# 7. Transition Function

The transition function is generally written as:

$$
\delta(q,a)
$$

where:

- `q` = current state
- `a` = current input character
- `δ(q,a)` = next state

Example:

```text
δ(q0, A) = q1
```

means:

> If the automaton is in state `q0` and reads `A`, it moves to `q1`.

---

# 8. Example Transition Table

For:

```text
Pattern = "AB"
Alphabet = {A, B}
```

A simplified transition table is:

| State |   A |   B |
| ----: | --: | --: |
|     0 |   1 |   0 |
|     1 |   1 |   2 |
|     2 |   1 |   0 |

Here:

```text
State 0 → no characters matched
State 1 → A matched
State 2 → AB matched
```

State `2` indicates a complete match.

---

# 9. Understanding the Transition Table

Consider state `1`.

State `1` means:

```text
A
```

### Input = B

```text
AB
```

The complete pattern is matched.

Therefore:

```text
δ(1, B) = 2
```

### Input = A

We now have:

```text
AA
```

The longest suffix that is also a prefix of `"AB"` is:

```text
A
```

Therefore:

```text
δ(1, A) = 1
```

This allows matching to continue without restarting completely.

---

# 10. Pattern Matching Process

Suppose:

```text
Text    = "AABAB"
Pattern = "AB"
```

The automaton processes one character at a time.

```text
Text:
A A B A B
```

State transitions:

```text
q0
 ↓ A
q1
 ↓ A
q1
 ↓ B
q2  ← Match
 ↓ A
q1
 ↓ B
q2  ← Match
```

Therefore, the pattern occurs at:

```text
1
3
```

---

# 11. Main Algorithm

Once the transition table has been constructed, matching is simple:

```text
state = 0

for each character in text:

    state = transition[state][character]

    if state == pattern length:

        report pattern occurrence
```

The matching phase does not need to compare the pattern character-by-character at every position.

---

# 12. Java Implementation

For practical understanding, the following implementation constructs the transition table for a given pattern and alphabet.

```java id="fa-java"
import java.util.*;

public class FiniteAutomataMatching {

    static int ALPHABET_SIZE = 256;

    static int getNextState(String pattern,
                            int state,
                            int ch) {

        int m = pattern.length();

        if (state < m &&
            ch == pattern.charAt(state)) {

            return state + 1;
        }

        for (int nextState = state;
             nextState > 0;
             nextState--) {

            if (pattern.charAt(nextState - 1) == ch) {

                boolean match = true;

                for (int i = 0;
                     i < nextState - 1;
                     i++) {

                    if (pattern.charAt(i) !=
                        pattern.charAt(state -
                                       nextState + 1 + i)) {

                        match = false;
                        break;
                    }
                }

                if (match) {
                    return nextState;
                }
            }
        }

        return 0;
    }

    static int[][] buildTransitionTable(String pattern) {

        int m = pattern.length();

        int[][] transition =
            new int[m + 1][ALPHABET_SIZE];

        for (int state = 0; state <= m; state++) {

            for (int ch = 0; ch < ALPHABET_SIZE; ch++) {

                transition[state][ch] =
                    getNextState(pattern, state, ch);
            }
        }

        return transition;
    }

    static void search(String text, String pattern) {

        int m = pattern.length();

        int[][] transition =
            buildTransitionTable(pattern);

        int state = 0;

        for (int i = 0; i < text.length(); i++) {

            state =
                transition[state]
                           [text.charAt(i)];

            if (state == m) {

                System.out.println(
                    "Pattern found at index "
                    + (i - m + 1)
                );
            }
        }
    }

    public static void main(String[] args) {

        String text = "AABAB";
        String pattern = "AB";

        search(text, pattern);
    }
}
```

### Output

```text id="b4ce3b"
Pattern found at index 1
Pattern found at index 3
```

# 13. C++ Implementation

```cpp id="fa-cpp"
#include <iostream>
#include <vector>
#include <string>

using namespace std;

const int ALPHABET_SIZE = 256;

int getNextState(string pattern,
                 int state,
                 int ch) {

    int m = pattern.length();

    if (state < m &&
        ch == pattern[state]) {

        return state + 1;
    }

    for (int nextState = state;
         nextState > 0;
         nextState--) {

        if (pattern[nextState - 1] == ch) {

            bool match = true;

            for (int i = 0;
                 i < nextState - 1;
                 i++) {

                if (pattern[i] !=
                    pattern[state -
                            nextState + 1 + i]) {

                    match = false;
                    break;
                }
            }

            if (match) {
                return nextState;
            }
        }
    }

    return 0;
}

vector<vector<int>>
buildTransitionTable(string pattern) {

    int m = pattern.length();

    vector<vector<int>> transition(
        m + 1,
        vector<int>(ALPHABET_SIZE)
    );

    for (int state = 0;
         state <= m;
         state++) {

        for (int ch = 0;
             ch < ALPHABET_SIZE;
             ch++) {

            transition[state][ch] =
                getNextState(
                    pattern,
                    state,
                    ch
                );
        }
    }

    return transition;
}

void searchPattern(string text,
                   string pattern) {

    int m = pattern.length();

    auto transition =
        buildTransitionTable(pattern);

    int state = 0;

    for (int i = 0;
         i < text.length();
         i++) {

        state =
            transition[state][text[i]];

        if (state == m) {

            cout << "Pattern found at index "
                 << i - m + 1
                 << endl;
        }
    }
}

int main() {

    string text = "AABAB";
    string pattern = "AB";

    searchPattern(text, pattern);

    return 0;
}
```

# 15. Finite Automaton and KMP

Both methods avoid unnecessary character comparisons, but their implementation approach is different.

| Feature               | Finite Automata      | KMP                       |
| --------------------- | -------------------- | ------------------------- |
| Preprocessing         | Transition table     | LPS array                 |
| Matching              | State transitions    | LPS-based shifts          |
| Main structure        | Finite-state machine | Prefix/suffix information |
| Matching time         | `O(n)`               | `O(n)`                    |
| Pattern preprocessing | Depends on alphabet  | `O(m)`                    |
| Extra storage         | Transition table     | LPS array                 |

---

# 16. Complexity

Let:

- `n` = length of text
- `m` = length of pattern
- `σ` = size of alphabet

### Matching

Once the transition table is built:

$$
\boxed{O(n)}
$$

because each text character causes one state transition.

### Transition Table

For the standard finite-automata construction, preprocessing depends on the pattern and alphabet.

A commonly used bound is:

$$
\boxed{O(m\sigma)}
$$

for an efficient transition-table construction.

### Space

The transition table requires:

$$
\boxed{O(m\sigma)}
$$

space.

---

# 17. Why Preprocessing Is Important

The expensive work is performed **before scanning the text**.

```text
Pattern
   ↓
Build transition table
   ↓
Text
   ↓
One character at a time
   ↓
State transition
   ↓
Match?
```

Once the table is available, the matching process is straightforward.

---

# 18. Example with Pattern "ABA"

Pattern:

```text
ABA
```

States:

```text
q0 → Nothing
q1 → A
q2 → AB
q3 → ABA
```

Important transitions:

```text
q0 --A--> q1
q1 --B--> q2
q2 --A--> q3
```

After reaching `q3`, the pattern has been found.

Because `"ABA"` has a prefix `"A"` that is also a suffix, some transitions after a match can continue from an appropriate state rather than returning to the beginning.

This is one reason preprocessing the pattern is useful.

# 20. Common Mistakes

### Mistake 1 — Confusing state number with text index

If:

```text
state = 3
```

it means **three pattern characters are currently matched**.

It does not mean text index `3`.

---

### Mistake 2 — Forgetting the final state

For a pattern of length `m`:

```text
state == m
```

indicates that the complete pattern has been matched.

---

### Mistake 3 — Building transitions only for matching characters

The automaton needs transitions for characters that **do not directly match the next pattern character** as well.

These transitions determine how much of the previously matched pattern can still be reused.

---

### Mistake 4 — Confusing automata matching with KMP

KMP stores:

```text
LPS array
```

Finite automata matching stores:

```text
Transition table
```

Both use information from the pattern, but they are not the same implementation.

```text

   ↓

   ↓

   ↓

   ↓

   ↓

  /       \
```

$$

> **Finite-automata string matching converts the pattern into a finite-state machine and processes the text by following state transitions.**
